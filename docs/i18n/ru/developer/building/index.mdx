Запускайте из корня репозитория. Исходники компилируются и тестируются установленной на машине Java 21 — той, которой запускается Gradle:

```shell
./gradlew check pluginJars
```

`pluginJars` собирает загрузочные jar-файлы для Velocity и BungeeCord, универсальный jar-файл (BUNDLE) и jar-файлы официальных провайдеров в `build/libs/`.

Чтобы получить файлы, которые входят в сборку для разработки или релиз, под их итоговыми именами, выполните:

```shell
./gradlew assembleDistribution
```

Команда записывает в `build/distribution/` файлы `Identica-BUNDLE-<version>.jar`, `Identica-BUNGEECORD-<version>.jar`, `Identica-VELOCITY-<version>.jar`, `Identica-PLATFORMS-<version>.zip` с jar-файлами для обоих прокси и два jar-файла провайдеров. Версия берётся из переменной окружения `VERSION`, по умолчанию — `dev`.

Каждая сборка плагина включает реализации всех встроенных функций и подсистему идентификации по нику. Администраторы настраивают использование функций глобально и для каждого провайдера; они не устанавливают jar-файлы функций и не выбирают, какие реализации компилировать.

Подмодули Gradle остаются раздельными ради границ API, разделения ответственности и тестирования. Их промежуточные jar-файлы — это зависимости сборки, а не дополнительные плагины Minecraft или функции, которые администратор может установить.

См. [Гарантии и функции провайдеров](../features/index.mdx) и [Конфигурация функций](../../configuration/features/index.mdx).
