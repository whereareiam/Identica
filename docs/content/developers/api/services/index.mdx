Every service is reached through the `IdenticaAPI` you got as described in [Getting started](../index.mdx).

## A first service

```java
import me.whereareiam.identica.IdenticaAPI;

public final class ExampleAddon {
    private final IdenticaAPI identica;

    public ExampleAddon(IdenticaAPI identica) {
        this.identica = identica;
    }

    public void inspectProviders() {
        identica.getProviderManager().getProviders().forEach(provider -> {
            if (provider != null && provider.getDescriptor() != null) {
                System.out.println(provider.getDescriptor().getId());
            }
        });
    }
}
```

## Finding other services

Services without a getter on `IdenticaAPI`, such as the API of a feature, are found by type. `findService` returns an empty `Optional` when Identica offers no service of that type.

```java
Optional<FeatureRegistry> features = identica.findService(FeatureRegistry.class);
```

Here `FeatureRegistry` is `me.whereareiam.identica.feature.FeatureRegistry`.

## Feature services and provider policy

Feature implementations are compiled into Identica. Find their APIs by type, and check effective provider enablement before running optional integrations.

```java
FeatureRegistry features = identica.findService(FeatureRegistry.class).orElseThrow();
if (features.isEnabled(providerId, "verification")) {
    identica.findService(VerificationService.class).ifPresent(verification -> {
        // Resolve verification for this provider.
    });
}
```

`isEnabled` combines provider-declared support with global defaults and provider overrides. Provider guarantees are inspected separately through `ProviderDescriptor.hasGuarantee(ProviderGuarantee.OWNED_USERNAME)`; no feature switch grants or removes a guarantee.

See [Provider guarantees and features](../../extending/guarantees-and-features/index.mdx) for the contracts.

## Common services worth using

These are some of the most useful services on `IdenticaAPI` for addon plugins:

- `getProviderManager()` for listing and inspecting loaded providers
- `getProviderOperations()` for provider eligibility and runtime provider operations
- `getSessionService()` for finding, listing, opening, or closing sessions
- `getAccountService()` for account lookup and lifecycle operations
- `getIdentityService()` for the identities of the players on this proxy
- `getMessageService()` for telling players Identica's messages and showing them in more ways than chat, see [Messages to players](../../extending/messages/index.mdx)
- `getReplicationSystem()` if you intentionally integrate with Identica's replicated caches or channels
- `getEventManager()` for registering or calling Identica events
- `getPendingScenarioService()` for whether a player still has to authenticate, register or migrate
- `getConfigCatalog()` for the loaded configuration documents, such as every messages document
- `getReloadables()` for being reloaded by `/identica admin reload`

Addons that hold back chat or commands until a player has authenticated are covered in [Writing an addon](../../extending/addons/index.mdx).

When `verification` is selected, find `VerificationService` for enrollment, challenge, selection, and reset flows, or `VerificationRegistry` for method discovery, through `identica.findService(...)`. Both types belong to `me.whereareiam.identica.feature.verification`.

A provider's verification step is a `StatefulStep`. `/2fa confirm` hands the typed code to the pending journey as a `VerificationCodeAttempt` in the run's state; the step takes it out of the state and passes it with `VerificationResolutionRequest.code(...)`. `resolveVerification` submits the code before it resolves the requirement. A code the challenge does not take ends as `REJECTED`, with the reason in `getRejection()`: `INVALID` for a wrong code. The step keeps waiting with the confirm command's invalid-code message for a wrong code and its no-pending message otherwise.

## Sessions

```java
import me.whereareiam.identica.IdenticaAPI;
import me.whereareiam.identica.identity.session.SessionService;

import java.util.UUID;

public final class ExampleAddon {
    private final IdenticaAPI identica;

    public ExampleAddon(IdenticaAPI identica) {
        this.identica = identica;
    }

    public void printSession(UUID uniqueId) {
        SessionService sessionService = identica.getSessionService();
        sessionService.findByUniqueId(uniqueId).thenAccept(optionalSession -> {
            optionalSession.ifPresent(session ->
                System.out.println(session.getProviderId() + " -> " + session.getEffectiveUsername())
            );
        });
    }
}
```

A session belongs to a connection: `session.getConnection()` returns the `SessionConnection` with the connection's unique id and the `replication.serverId` of the proxy that holds it. An account has one session, held by one connection:

- `findByUniqueId(uniqueId)` returns the account's session, enough to learn whether the account is online or how it logged in
- `findByConnection(uniqueId, SessionConnection.of(player.getUniqueId()))` returns it only when that connection holds it, which a connection whose session was replaced no longer does
- `list(page, pageSize)` pages through session ids, which `findBySessionId` resolves

`SessionService.open(session)` continues a stored session only when the new session names the same connection; any other connection is a concurrent login decided by the configured concurrency policy. The policy decides on the session the account had when the call read it: when another login of the account, typically on another proxy, opened a session in between, the returned future fails with `ConcurrentSessionChangeException` and nothing of the call is kept, so open the session again once you have told the player. `close(uniqueId)` ends the account's session. To end it only when one connection holds it, for example when that player leaves, set the connection on the close request; a session another connection holds is then left alone:

```java
sessionService.close(SessionCloseRequest.builder()
        .uniqueId(accountUniqueId)
        .connection(SessionConnection.of(player.getUniqueId()))
        .build());
```
