`features/restriction/join/` содержит файлы ограничения входа: `settings.yml`, `commands.yml` и `messages.yml`. Как им пользуется администрация, описано в разделе [Ограничение входа](../../../../admins/features/restriction/join/index.mdx).

## settings.yml

```yaml
enabled: false
allow: []
resumeBypass:
  authentication: false
  registration: false
```

<Setting
  name="enabled"
  takes="`true` или `false`"
  default="`false`"
  affects="можно ли ограничивать вход через провайдеры — для каждого провайдера, который не задаёт собственное значение"
  flag="advanced"
>

</Setting>

<Setting
  name="allow"
  takes="список сигналов: `linked`, `recognized`"
  default="`[]`"
  affects="какие игроки всё равно проходят, пока провайдер ограничен, — для каждого провайдера, который не задаёт собственный список"
  flag="advanced"
>

`linked` пропускает игроков, у которых есть аккаунт у этого провайдера, `recognized` — игроков, которых узнаёт [распознавание](../../../../admins/features/recognition/index.mdx). Указание `recognized` не включает распознавание.

</Setting>

<Setting
  name="resumeBypass.authentication"
  takes="`true` или `false`"
  default="`false`"
  affects="может ли завершиться вход, который уже ожидал, когда ограничение началось"
>

</Setting>

<Setting
  name="resumeBypass.registration"
  takes="`true` или `false`"
  default="`false`"
  affects="может ли завершиться регистрация, которая уже ожидала, когда ограничение началось"
>

Ни одна из этих настроек не пропускает новые попытки. Сценарий также должен разрешать продолжение через [`allowResume`](../../../engine/index.mdx#allowresume).

</Setting>

## Для отдельного провайдера [#per-provider]

В `features.restriction.join` записи провайдера в `providers/providers.yml`. Если поле не задано, оно берётся из общих настроек, а [`features.restriction.enabled`](../index.mdx#featuresrestrictionenabled) провайдера не должно быть `false`.

```yaml
providers:
  - id: "credential"
    features:
      restriction:
        join:
          enabled: true
          allow:
            - linked
            - recognized
```

<Setting
  name="features.restriction.join.enabled"
  takes="`true` или `false`"
  default="не задано"
  affects="может ли администрация ограничивать вход через этого провайдера"
  flag="advanced"
>

</Setting>

<Setting
  name="features.restriction.join.allow"
  takes="список сигналов: `linked`, `recognized`"
  default="не задано"
  affects="какие игроки этого провайдера всё равно проходят, пока он ограничен"
  flag="advanced"
>

</Setting>

## commands.yml и messages.yml [#commandsyml-and-messagesyml]

У команд `/identica admin provider restriction join enable|disable|status` те же поля, что и в [`commands.yml`](../../../commands/index.mdx#commands). Сообщение `denied` видит игрок, которому отказали.
