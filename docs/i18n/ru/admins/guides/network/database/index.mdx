Identica хранит в базе данных аккаунты, их привязки к провайдерам, пароли, ники, резервирования UUID и способы подтверждения. Базу данных выбирает `persistence.yml`.

## Выбор базы данных [#choosing-a-database]

| `type` | Где хранятся данные | Для чего подходит |
| --- | --- | --- |
| `SQLITE` (по умолчанию) | файл в каталоге данных | один прокси |
| `H2` | файл в каталоге данных | один прокси |
| `MYSQL` | сервер MySQL 8.0.19 или новее либо MariaDB | один или [несколько прокси](../several-proxies/index.mdx) |
| `POSTGRES` | сервер PostgreSQL | один или несколько прокси |

Если `persistence.yml` ещё нет или в нём не задан `type`, Identica использует SQLite. Значения чувствительны к регистру; любое другое значение останавливает запуск с ошибкой, в которой перечислены допустимые значения.

## Подключение к серверу [#connecting-to-a-server]

```yaml
type: "MYSQL"
host: "db.internal"
port: 3306
database: "identica"
username: "identica"
credential: "secret"
```

Создайте базу данных и пользователя, которому разрешено создавать и изменять в ней таблицы; таблицы Identica создаёт сама.

После смены `type` запустите прокси один раз, чтобы Identica записала поля нового типа, а затем заполните их. При первом запуске с новым типом Identica скачивает драйвер этой базы данных, поэтому нужен доступ в интернет.

База данных открывается при запуске, поэтому изменения в `persistence.yml` вступают в силу при следующем запуске, а не после `/identica admin reload`.

Если база данных недоступна или сервер MySQL старше 8.0.19, запуск прерывается ещё до того, как будет создана или изменена какая-либо таблица. Как и при любом неудачном запуске, все игроки получают отказ, пока причина не будет устранена, а прокси — перезапущен.

## Таблицы и обновления [#tables-and-upgrades]

Identica создаёт свои таблицы при первом запуске и обновляет их при последующих — после обновления самой Identica, функции или провайдера. Сведения о том, до какой версии дошёл каждый набор таблиц, хранятся в таблице `strata_history`; не трогайте её.

Перед первым запуском нового релиза остановите все прокси, которые используют эту базу данных, и сделайте её резервную копию. См. [Обновление Identica](../../upgrading/index.mdx).

## Переход на другую базу данных [#moving-to-another-database]

Identica не переносит аккаунты из базы данных одного типа в другую. Если сменить `type` в сети, где уже есть игроки, работа начнётся с пустой базы данных; если аккаунты нужно сохранить, сначала скопируйте таблицы инструментом для ваших баз данных.

Все настройки базы данных, включая пул подключений, описаны на странице [`persistence.yml`](../../../../configuration/persistence/index.mdx).
