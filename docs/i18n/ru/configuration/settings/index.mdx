`settings.yml` содержит уровень логирования, способ назначения UUID аккаунтам, политику сессий и слушатели прокси.

<Setting
  name="level"
  depth={2}
  takes="целое число от `0` до `4`"
  default="`2`"
  affects="то, сколько Identica пишет в консоль"
>

| Значение | Что пишется |
|-------|----------------------------|
| `0`   | только ошибки              |
| `1`   | предупреждения и ошибки    |
| `2`   | информация, предупреждения и ошибки |
| `3`   | добавляется отладочный вывод (debug) |
| `4`   | добавляется трассировка (trace) |

В обычной работе используйте `2`, а `3` или `4` — пока разбираетесь с проблемой.

</Setting>

## identity

<Setting
  name="uniqueIdMode"
  takes='`"RANDOM"`, `"OFFLINE"` или `"PREMIUM"`'
  default='`"RANDOM"`'
  affects="то, как новые аккаунты получают UUID"
  flag="danger"
>

`RANDOM` выдаёт каждому аккаунту новый случайный UUID, `OFFLINE` — офлайн-UUID его ника, `PREMIUM` — UUID его лицензионного аккаунта. Существующие аккаунты сохраняют свой UUID. Прежде чем менять эту настройку, прочитайте [Уникальные идентификаторы](../../admins/guides/accounts/unique-ids/index.mdx).

</Setting>

<Setting
  name="reservationTtl"
  takes="положительную длительность"
  default='`"15m"`'
  affects="то, как долго зарезервированный UUID ждёт регистрации аккаунта под своим ником"
  flag="advanced"
>

Резервирование, сделанное командой `/identica admin reservation set`, командой `/identica admin clear` или во время незавершённой регистрации, истекает по прошествии этого времени, если под этим ником никто не зарегистрировался. Если значение слишком короткое, медленная регистрация теряет зарезервированный UUID; если слишком длинное, брошенные резервирования хранятся дольше.

</Setting>

## sessions

<Setting
  name="concurrencyPolicy"
  takes='`"REPLACE_EXISTING"` или `"REJECT_NEW"`'
  default='`"REPLACE_EXISTING"`'
  affects="то, что происходит, когда аккаунт с открытой сессией входит с другого подключения"
  flag="warning"
>

`REPLACE_EXISTING` отключает прежнее подключение, `REJECT_NEW` отклоняет новый вход. Любое другое значение останавливает запуск с ошибкой, в которой перечислены допустимые значения. Провайдер может использовать другую политику через `session.concurrencyPolicy` в [`providers/providers.yml`](../providers/index.mdx#sessionconcurrencypolicy). См. [Сессии](../../admins/guides/logins/sessions/index.mdx).

</Setting>

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
level: 2
identity:
  uniqueIdMode: "RANDOM"
  reservationTtl: "15m"
sessions:
  concurrencyPolicy: "REPLACE_EXISTING"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "level": 2,
  "identity": {
    "uniqueIdMode": "RANDOM",
    "reservationTtl": "15m"
  },
  "sessions": {
    "concurrencyPolicy": "REPLACE_EXISTING"
  }
}
```
  </Tab>
</Tabs>

## listeners

Identica следит за событиями прокси, чтобы обрабатывать входящих игроков. `listeners.events` позволяет изменить приоритет одного из этих слушателей, например чтобы он срабатывал раньше или позже другого плагина, обрабатывающего то же событие, или отключить его.

<Setting
  name="events"
  takes="словарь, ключами которого служат полные имена классов событий прокси"
  affects="то, слушает ли Identica это событие и с каким приоритетом"
  flag="advanced"
>

<ContentTabs items={["Velocity", "BungeeCord"]}>
  <ContentTab value="Velocity">
```yaml
listeners:
  events:
    com.velocitypowered.api.event.connection.PreLoginEvent:
      register: true
      priority: "NORMAL"
```
  </ContentTab>
  <ContentTab value="BungeeCord">
```yaml
listeners:
  events:
    net.md_5.bungee.api.event.PlayerHandshakeEvent:
      register: true
      priority: "NORMAL"
```
  </ContentTab>
</ContentTabs>

</Setting>

<Setting
  name="register"
  takes="`true` или `false`"
  affects="то, слушает ли Identica это событие вообще"
  flag="warning"
>

Отключённый слушатель ломает ту часть входа, которая от него зависит. Делайте это, только если работу этого события берёт на себя другой плагин.

</Setting>

<Setting
  name="priority"
  takes='`"LOWEST"`, `"LOW"`, `"NORMAL"`, `"HIGH"` или `"HIGHEST"`'
  default='`"NORMAL"`'
  affects="то, когда слушатель Identica срабатывает относительно слушателей того же события из других плагинов, в порядке приоритетов самого прокси"
  flag="advanced"
>

</Setting>
