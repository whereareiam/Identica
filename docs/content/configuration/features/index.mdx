Each feature keeps its files under `features/<feature>/`: `settings.yml`, and `messages.yml` and `commands.yml` when it has messages or commands. Join restriction is nested under `features/restriction/join/`. [Features](../../admins/features/index.mdx) explains what each feature does.

## Per-provider settings

A provider's entry in [`providers/providers.yml`](../providers/index.mdx#features) can set its own value for a feature under `features`. What it leaves out comes from the feature's shared settings:

| Feature | Shared settings | Per provider | Inherits |
| --- | --- | --- | --- |
| Recognition | `features/recognition/settings` | `features.recognition` | `enabled`, and `defaultSignals` for `signals` |
| Restriction | `features/restriction/settings` | `features.restriction.enabled` | `enabled` |
| Join restriction | `features/restriction/join/settings` | `features.restriction.join` | `enabled`, `allow` |
| Sentinel | `features/sentinel/settings` | `features.sentinel.enabled` | `enabled` |
| Verification | `features/verification/settings` | `features.verification` | everything under `defaults` |

`enabled: false` for a provider turns the feature off for that provider only, and `enabled: true` turns it on even when the shared value is `false`. A provider's `features.restriction.enabled: false` turns off join restriction for it too.

A provider has to support a feature. Turning on a feature for a provider that does not support it stops that provider from loading. Both official providers support every feature.
