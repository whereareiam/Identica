This page provides the settings for the built-in sentinel feature.

Shared settings live under `features/sentinel/settings`. Messages live under `features/sentinel/messages`. The shared `enabled` switch defaults to true; provider-owned checks can override it through `providers[].features.sentinel.enabled`.

## Settings

### sentinels.resumeSpam.enabled

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the built-in resume-spam sentinel is allowed to operate

This sentinel watches process, resume, and advance attempts.

### sentinels.resumeSpam.maxAttempts

<Badge type="warning">Advanced</Badge>

- Takes: an integer greater than `0`
- Current default: `10`
- Affects: how many attempts are allowed before lockout logic applies

### sentinels.resumeSpam.lockout.enabled

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `true`
- Affects: whether the sentinel can actively lock out attempts after the threshold is exceeded

### sentinels.resumeSpam.lockout.duration

<Badge type="warning">Advanced</Badge>

- Takes: a positive duration
- Current default: `"30s"`
- Affects: how long the lockout lasts

### sentinels.resumeSpam.warning.enabled

<Badge type="warning">Advanced</Badge>

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether pre-lockout warning logic can run

### sentinels.resumeSpam.warning.thresholdPercentage

<Badge type="warning">Advanced</Badge>

- Takes: an integer percentage from `0` to `100`
- Current default: `0`
- Affects: when warning messages start relative to `maxAttempts`

The current code clamps this into the `0..100` range and computes the warning threshold from `maxAttempts`.
For example, with `maxAttempts: 10` and `thresholdPercentage: 70`, warnings begin on attempt `8`.

### sentinels.contestedConnection.enabled

- Takes: `true` or `false`
- Current default: `true`
- Affects: whether the contested-connection sentinel locks out an address that keeps contesting usernames

This sentinel counts the connections of an address that are refused because another connection is logging in under their username from another address (see [Logins in progress](../../../engine/index.mdx#logins-in-progress)). It counts per address, whatever username each connection uses. Once the address reaches `maxAttempts`, every connection from it is refused for the lockout duration.

### sentinels.contestedConnection.maxAttempts

- Takes: an integer greater than `0`
- Current default: `5`
- Affects: how many refused connections an address may have before it is locked out

### sentinels.contestedConnection.lockout.enabled

- Takes: `true` or `false`
- Current default: `true`
- Affects: whether the sentinel locks the address out once it reaches `maxAttempts`

### sentinels.contestedConnection.lockout.duration

- Takes: a positive duration
- Current default: `"1m"`
- Affects: how long the address stays locked out

### replication.state

<Badge type="warning">Advanced</Badge>

- Takes: a string
- Current default: `"identica:sentinels"`
- Affects: the namespace used for replicated sentinel state

This namespace stores shared sentinel counters and lockout state.

## Messages

The following fields belong to `features/sentinel/messages`.

### resumeSpam.denied

- Takes: a list of lines
- Current default: a built-in lockout message block
- Affects: the denial message shown while the resume-spam lockout is active

The `{seconds}` placeholder is replaced with the remaining lockout duration.
An empty list silences the message; the lockout still denies.

### contestedConnection.denied

- Takes: a list of lines
- Current default: a notice reading `Too many attempts to log in under names in use.` and the time left
- Affects: the reason shown to a connection from an address the contested-connection sentinel locked out

The `{seconds}` placeholder is replaced with the remaining lockout duration. An empty list silences the message; the lockout still denies.

## Settings example

The following example belongs to `features/sentinel/settings`:

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
sentinels:
  resumeSpam:
    enabled: true
    maxAttempts: 10
    lockout:
      enabled: true
      duration: "30s"
    warning:
      enabled: true
      thresholdPercentage: 70
  contestedConnection:
    enabled: true
    maxAttempts: 5
    lockout:
      enabled: true
      duration: "1m"
replication:
  state: "identica:sentinels"
```
