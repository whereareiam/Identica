На этой странице описаны настройки встроенной функции Sentinel.

Общие настройки находятся в `features/sentinel/settings`, сообщения — в `features/sentinel/messages`. Общий переключатель `enabled` по умолчанию равен true; проверки, принадлежащие провайдерам, могут переопределить его через `providers[].features.sentinel.enabled`.

## Настройки [#settings]

### sentinels.resumeSpam.enabled

<Badge type="warning">Для опытных</Badge>

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: разрешено ли работать встроенной проверке спама продолжениями (resume-spam)

Эта проверка отслеживает попытки обработки, продолжения и перехода к следующему шагу.

### sentinels.resumeSpam.maxAttempts

<Badge type="warning">Для опытных</Badge>

- Принимает: целое число больше `0`
- По умолчанию: `10`
- Влияет на: сколько попыток разрешено, прежде чем срабатывает блокировка

### sentinels.resumeSpam.lockout.enabled

<Badge type="warning">Для опытных</Badge>

- Принимает: `true` или `false`
- По умолчанию: `true`
- Влияет на: может ли проверка активно блокировать попытки после превышения порога

### sentinels.resumeSpam.lockout.duration

<Badge type="warning">Для опытных</Badge>

- Принимает: положительную длительность
- По умолчанию: `"30s"`
- Влияет на: сколько длится блокировка

### sentinels.resumeSpam.warning.enabled

<Badge type="warning">Для опытных</Badge>

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: могут ли выдаваться предупреждения до блокировки

### sentinels.resumeSpam.warning.thresholdPercentage

<Badge type="warning">Для опытных</Badge>

- Принимает: целое число процентов от `0` до `100`
- По умолчанию: `0`
- Влияет на: с какого момента относительно `maxAttempts` начинают выдаваться предупреждения

Текущий код приводит значение к диапазону `0..100` и вычисляет порог предупреждения от `maxAttempts`.
Например, при `maxAttempts: 10` и `thresholdPercentage: 70` предупреждения начинаются с попытки `8`.

### sentinels.contestedConnection.enabled

- Принимает: `true` или `false`
- По умолчанию: `true`
- Влияет на: блокирует ли sentinel адрес, подключения которого снова и снова пытаются войти под занятыми именами

Этот sentinel считает подключения адреса, отклонённые потому, что под их именем уже входит другое подключение с другого адреса (см. [Входы в процессе](../../../engine/index.mdx#logins-in-progress)). Он считает по адресу, какое бы имя ни использовало каждое подключение. Когда адрес достигает `maxAttempts`, все подключения с него отклоняются на время блокировки.

### sentinels.contestedConnection.maxAttempts

- Принимает: целое число больше `0`
- По умолчанию: `5`
- Влияет на: сколько отклонённых подключений может быть у адреса, прежде чем его заблокируют

### sentinels.contestedConnection.lockout.enabled

- Принимает: `true` или `false`
- По умолчанию: `true`
- Влияет на: блокирует ли sentinel адрес, когда тот достигает `maxAttempts`

### sentinels.contestedConnection.lockout.duration

- Принимает: положительную длительность
- По умолчанию: `"1m"`
- Влияет на: как долго адрес остаётся заблокированным

### replication.state

<Badge type="warning">Для опытных</Badge>

- Принимает: строку
- По умолчанию: `"identica:sentinels"`
- Влияет на: пространство имён для реплицируемого состояния Sentinel

В этом пространстве имён хранятся общие счётчики Sentinel и состояние блокировок.

## Сообщения [#messages]

Следующие поля относятся к `features/sentinel/messages`.

### resumeSpam.denied

- Принимает: список строк
- По умолчанию: встроенный блок сообщения о блокировке
- Влияет на: сообщение об отказе, которое показывается, пока действует блокировка за спам продолжениями

Плейсхолдер `{seconds}` заменяется оставшимся временем блокировки.
Пустой список отключает сообщение, но блокировка по-прежнему отклоняет попытки.

### contestedConnection.denied

- Принимает: список строк
- По умолчанию: уведомление со строкой `Too many attempts to log in under names in use.` и оставшимся временем
- Влияет на: причину, которую видит подключение с адреса, заблокированного sentinel занятых имён

Плейсхолдер `{seconds}` заменяется оставшимся временем блокировки. Пустой список отключает сообщение, но блокировка по-прежнему отклоняет попытки.

## Пример настроек [#settings-example]

Этот пример относится к `features/sentinel/settings`:

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
sentinels:
  resumeSpam:
    enabled: true
    maxAttempts: 10
    lockout:
      enabled: true
      duration: "30s"
    warning:
      enabled: true
      thresholdPercentage: 70
  contestedConnection:
    enabled: true
    maxAttempts: 5
    lockout:
      enabled: true
      duration: "1m"
replication:
  state: "identica:sentinels"
```
  </Tab>
