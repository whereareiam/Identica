Распознавание запоминает игрока, который вошёл. Если тот же игрок переподключается в течение заданного времени, с того же адреса, с тем же ником и через тот же хостнейм, Identica узнаёт его и пропускает вход.

Это удобно для игроков, которые часто переподключаются, например после неудачной смены сервера или вылета игры. Но это и снижает защиту: любой, кто может выдать себя за этого игрока, например с того же общего адреса, попадает на сервер без пароля. Включайте распознавание, только если понимаете, кто в вашей сети может оказаться на одном адресе.

## Включение [#turning-it-on]

По умолчанию распознавание выключено. Включите его для всех провайдеров в `features/recognition/settings`:

```yaml
enabled: true
validity: "12h"
```

или для одного провайдера в `providers/providers.yml`:

```yaml
providers:
  - id: "credential"
    features:
      recognition:
        enabled: true
```

Распознанный игрок может переподключаться без входа в течение `validity` после последнего входа, по умолчанию 12 часов.

## Что должно совпасть [#what-has-to-match]

По умолчанию у переподключившегося игрока должны совпасть все три сигнала:

- `USERNAME`: тот же ник,
- `IP`: тот же адрес,
- `VIRTUAL_HOST`: тот же хостнейм, через который он зашёл.

`defaultSignals` меняет набор для всех провайдеров, а `signals` в записи провайдера — для этого провайдера. Чем меньше сигналов, тем проще получить распознавание и тем проще им злоупотребить.

## Адреса, которым никогда не доверяют [#addresses-that-are-never-trusted]

За неправильно настроенным прокси все игроки могут выглядеть так, будто подключаются с `127.0.0.1` или с частного адреса. С адресов из `eligibility.untrustedIps.entries`, где по умолчанию перечислены loopback и частные сети, распознавание никогда не выдаётся. Провайдер, который всё же должен распознавать игроков с них, задаёт `allowOnUntrustedIps: true`.

Если распознавание никогда не срабатывает, проверьте, что Identica видит реальные адреса игроков.

## Вместе с ограничением входа [#with-join-restriction]

Распознавание добавляет сигнал `recognized` в [ограничение входа](../restriction/join/index.mdx): провайдер с ограниченным входом всё равно может пускать распознанных игроков, если указать `recognized` в его списке `allow`.

Все настройки описаны на странице [Настройки распознавания](../../../configuration/features/recognition/index.mdx).
