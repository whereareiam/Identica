У каждого аккаунта есть UUID, который бэкенд-серверы и другие плагины видят как уникальный идентификатор игрока. Identica назначает его при создании аккаунта, и аккаунт сохраняет его навсегда — в том числе когда меняется ник или провайдер.

## Выбор режима [#choosing-a-mode]

`identity.uniqueIdMode` в `settings.yml` определяет, как новые аккаунты получают UUID.

<Callout type="error" title="Выберите до того, как игроки начнут регистрироваться">
  Смена режима не меняет UUID существующих аккаунтов. Плагины на бэкенд-серверах хранят данные по UUID, поэтому аккаунты, созданные в разных режимах, не совпадут с тем, что ожидают эти плагины.
</Callout>

<Tabs items={["RANDOM", "OFFLINE", "PREMIUM"]}>
  <Tab value="RANDOM">
    Новый случайный UUID, принадлежащий Identica. Он никак не связан ни с ником, ни с провайдером.

    Это режим по умолчанию и рекомендуемый. Смена ника и переход между провайдерами никогда не затрагивают UUID, поэтому игрок сохраняет свои данные на каждом бэкенд-сервере.
  </Tab>
  <Tab value="OFFLINE">
    UUID, который офлайн-сервер выдаёт нику: `Steve` получает UUID `OfflinePlayer:Steve`.

    Используйте его, если на бэкенд-серверах уже есть данные под офлайн-UUID, например после работы сети в офлайн-режиме. UUID фиксируется при создании аккаунта, поэтому игрок, которого позже переименовали, сохраняет UUID своего первого ника.
  </Tab>
  <Tab value="PREMIUM">
    UUID лицензионного аккаунта Mojang игрока: UUID, который подтвердил провайдер, а если его нет — UUID лицензионного аккаунта, который прислал клиент, если это не просто офлайн-UUID его ника.

    Используйте его, если на бэкенд-серверах уже есть данные под UUID лицензионных аккаунтов. Аккаунт, для которого UUID лицензионного аккаунта неизвестен, создать нельзя, поэтому этот режим подходит только сети, где каждый игрок входит через Premium.
  </Tab>
</Tabs>

| | `RANDOM` | `OFFLINE` | `PREMIUM` |
| --- | --- | --- | --- |
| Рекомендуется | Да | Нет | Нет |
| Совпадает с существующими данными офлайн-режима | Нет | Да | Нет |
| Совпадает с существующими данными лицензионных аккаунтов | Нет | Нет | Да |
| Работает с любым провайдером | Да | Да | Только с провайдерами, которые знают UUID лицензионного аккаунта |

## Выдача игроку выбранного UUID [#giving-one-player-a-chosen-uuid]

Чтобы выдать одному игроку определённый UUID, например его офлайн-UUID в сети с `RANDOM`, зарезервируйте UUID за его ником и попросите игрока зарегистрироваться заново:

1. `/identica admin delete <username>`, затем `/identica admin delete confirm` удаляют текущий аккаунт. UUID удалённого аккаунта не сохраняется.
2. `/identica admin reservation set <username> <uuid>` резервирует UUID. Ники сравниваются без учёта регистра.
3. Игрок заходит и регистрируется в течение `identity.reservationTtl` — по умолчанию 15 минут. Новый аккаунт получает зарезервированный UUID, и резервирование расходуется.

`/identica admin reservation info <username>` показывает UUID, зарезервированный за ником, а `/identica admin reservation delete <username>` снимает резервирование. В режимах `RANDOM` и `OFFLINE` резервирование заменяет UUID, который назначил бы режим; `PREMIUM` всегда назначает UUID лицензионного аккаунта.

`/identica admin clear <username>` удаляет аккаунт, но резервирует его UUID за его ником, так что при повторной регистрации игрок сохранит свой UUID.

Аккаунты, зарегистрированные из консоли командой `/identica credential register`, тоже получают UUID, зарезервированный за их ником, — так аккаунты из другого плагина авторизации сохраняют свои UUID; см. [Переход с другого плагина](../../upgrading/from-another-plugin/index.mdx).
