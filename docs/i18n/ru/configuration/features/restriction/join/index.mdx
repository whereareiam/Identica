Ограничение входа построено на встроенном каркасе ограничений. Оба компонента встроены в Identica; администраторы настраивают их поведение глобально и для каждого провайдера.
Функция определяет, может ли провайдер временно ограничивать новые входы с помощью административных команд ограничения.

Пока провайдер ограничен, игрок, которого он обслуживал бы и у которого нет ни одного из разрешённых признаков, получает отказ с сообщением `denied`. Если Identica уже знает провайдера, когда игрок заходит, прокси отклоняет подключение во время входа, до любого запроса, одинаково на Velocity и BungeeCord. Игрок, чей провайдер выбирается только позже в ходе прохождения, получает отказ, когда завершается его регистрация или аутентификация. После снятия ограничения игрок, получивший отказ, проходит при следующей попытке.

Переопределения ограничения входа для провайдера задаются в `providers[].features.restriction.join`.

Общие документы с командами и сообщениями находятся в `features/restriction/join/commands` и `features/restriction/join/messages`.

## Настройки [#settings]

Общие настройки политики находятся в `features/restriction/join/settings`.

### resumeBypass.authentication

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: может ли уже начатый процесс аутентификации продолжиться, несмотря на действующее ограничение входа для провайдера

### resumeBypass.registration

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: может ли уже начатый процесс регистрации продолжиться, несмотря на действующее ограничение входа для провайдера

Эти политики касаются только продолжаемых процессов. Они не пропускают новые попытки через действующее ограничение и не включают поддержку продолжения в движке. Возобновление должен разрешать соответствующий сценарий движка через `allowResume`.

```yaml
resumeBypass:
  authentication: false
  registration: false
```

## Переопределения для провайдеров [#provider-overrides]

### features.restriction.join.enabled

<Badge type="warning">Для опытных</Badge>

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: предоставляет ли этот провайдер типизированную среду выполнения ограничения входа

### features.restriction.join.allow

<Badge type="warning">Для опытных</Badge>

- Принимает: список идентификаторов сигналов
- По умолчанию: не задано, если не настроено явно
- Влияет на: какие из добавленных сигналов входа могут пропускать игроков через провайдера, пока действует ограничение входа

Встроенный сигнал `linked` пропускает привязанные аккаунты. Сигнал `recognized` добавляется, когда выбрана и функция `recognition`; распознавание может работать без ограничения входа. Указание `recognized` в этом списке не включает распознавание.

## Общие значения по умолчанию [#shared-defaults]

По умолчанию `features/restriction/join/settings.enabled` равно `false`, а `allow` — пустой список. Поля провайдера переопределяют эти значения; пропущенное поддерево провайдера их наследует. Внешняя функция ограничений тоже должна быть включена. Политику продолжаемых процессов по-прежнему задают `resumeBypass.authentication` и `resumeBypass.registration`.
