Конфигурация провайдеров определяет, какие провайдеры идентичности включены и как применяется поведение, специфичное для провайдера.
В этом файле включают провайдеры, задают приоритет и точки входа, настраивают поведение сессий для отдельных провайдеров и применяют поля провайдеров, которыми владеют функции.

Общие настройки функций и их переопределения для провайдеров описаны в разделе [Функции](../features/index.mdx).
Настройка конфликтов, которыми владеют провайдеры, описана в разделе [Конфликты](./conflicts.mdx).

## behavior

`behavior` содержит общие для всех провайдеров временные параметры работы.

### attemptTtl

<Badge type="warning">Для опытных</Badge>

- Принимает: положительную длительность
- По умолчанию: `"10m"`
- Влияет на: то, как долго отметки о попытках провайдера хранятся в реплицируемом хранилище попыток

Identica использует это значение, когда отмечает, что попытка провайдера уже была для данного сочетания провайдера, области, ника и IP.
Чем больше значение, тем дольше повторные попытки остаются заблокированными.
Чем меньше значение, тем раньше можно повторить попытку.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
behavior:
  attemptTtl: "10m"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "behavior": {
    "attemptTtl": "10m"
  }
}
```
  </Tab>
</Tabs>

## providers

- Принимает: список записей провайдеров
- Влияет на: включение провайдеров, их порядок, маршрутизацию по точкам входа, поведение сессий для отдельных провайдеров, переопределения для провайдеров, которыми владеют функции

Id провайдеров должны совпадать с дескрипторами установленных провайдеров, например `premium` или `credential`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
providers:
  - id: "premium"
    displayName: "PR"
    enabled: true
    priority: 100
    entrypoints:
      - "premium.example.com"
    session:
      concurrencyPolicy: "REJECT_NEW"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "providers": [
    {
      "id": "premium",
      "displayName": "PR",
      "enabled": true,
      "priority": 100,
      "entrypoints": ["premium.example.com"],
      "session": {
        "concurrencyPolicy": "REJECT_NEW"
      }
    }
  ]
}
```
  </Tab>
</Tabs>

### id

- Принимает: строку с id провайдера
- Влияет на: то, какой дескриптор установленного провайдера настраивает эта запись

Значение должно совпадать с id дескриптора провайдера настолько, чтобы его можно было найти без учёта регистра.

### displayName

- Принимает: строку
- По умолчанию: `""`
- Влияет на: отображаемое для пользователей название провайдера там, где оно нужно

Если значение пустое, Identica использует имя из дескриптора провайдера, а если его нет — сам id.

### enabled

- Принимает: `true` или `false`
- Влияет на: то, доступен ли провайдер для определения и построения процесса входа

### priority

- Принимает: целое число
- Влияет на: порядок, когда подходят несколько провайдеров

Большие значения имеют преимущество перед меньшими.

### entrypoints

- Принимает: список имён хостов, при необходимости с `:port`
- Влияет на: какой провайдер получает игрок, который заходит через одно из этих имён хостов, см. [Как выбирается провайдер](#how-a-provider-is-picked)

Записи должны иметь формат `host` или `host:port`. Запись без порта подходит для имени хоста на любом порту, запись с портом — только для этого порта. Если одно имя хоста указано у нескольких провайдеров, его получает провайдер с большим `priority`.
Оставьте список пустым, если имена хостов провайдеров в вашей конфигурации не используются.

Имя хоста только выбирает провайдера. Оно никогда не направляет игрока на сервер — для этого есть forced hosts и [`forcedHosts`](../routing/index.mdx#forcedhosts) маршрутизации — и никогда не снимает защиту ника, которую даёт сам провайдер: провайдер Premium по-прежнему требует свой вход для премиум-ника или аккаунта Premium, через какое бы имя хоста ни зашёл игрок.

### session

Используйте `session`, когда один провайдер должен вести себя иначе, чем задают глобальные значения по умолчанию для активных сессий.

#### session.concurrencyPolicy

<Badge type="warning">Для опытных</Badge>

- Принимает: `"ALLOW_MULTIPLE"`, `"REPLACE_EXISTING"` или `"REJECT_NEW"`
- По умолчанию: не задано
- Влияет на: то, как работает замена активных сессий для этого провайдера

Если значение не задано, Identica использует `settings.sessions.concurrencyPolicy`.

### features

Используйте `features` для переопределения встроенного поведения для отдельного провайдера. Провайдеры объявляют поддержку интеграции через `supportedFeatures()`. Пропущенные настройки наследуют глобальные значения по умолчанию; явно заданные для провайдера значения их переопределяют.

- Принимает: объект с поддеревьями конфигурации, которыми владеют функции
- По умолчанию: не задано, если функция не добавляет его сама
- Влияет на: переопределения выбранных функций для провайдера

Поддерживаемые поддеревья:

- `features.recognition`: [Распознавание](../features/recognition/index.mdx#provider-overrides)
- `features.restriction.join`: [Ограничение входа](../features/restriction/join/index.mdx#provider-overrides)
- `features.verification`: [Верификация](../features/verification/settings/index.mdx#provider-overrides)

Функция `restriction-join` использует вложенный путь конфигурации `restriction.join`.
Id возможностей провайдера, такие как `authoritative-username`, объявляются в коде и не являются поддеревьями конфигурации.

## Как выбирается провайдер [#how-a-provider-is-picked]

Для каждого входа собираются причины, по которым его должен обработать тот или иной провайдер, и побеждает самая сильная. Identica выбирает провайдера один раз, пока игрок подключается, и сохраняет выбор на всё прохождение. От самой сильной причины к самой слабой:

1. **Ожидающая миграция.** Игрок подтвердил переход к другому провайдеру, поэтому настраивается новый провайдер.
2. **Аккаунт подтверждённого входа.** Провайдер доказал, что клиент владеет своей личностью, например провайдер Premium после онлайн-входа, и эта личность уже принадлежит аккаунту. Существующий аккаунт сохраняет своего провайдера, поэтому имя хоста никогда не переносит аккаунт.
3. **Имя хоста.** Игрок зашёл через одну из [`entrypoints`](#entrypoints) провайдера. Вход через имя хоста — это осознанный выбор.
4. **Подтверждённый вход без аккаунта.** Провайдер доказал личность клиента, но аккаунта с ней ещё нет. Игрок регистрируется у этого провайдера, если имя хоста не выбрало другого.
5. **Выбор игрока.** Игрок выбрал провайдера в интерактивном выборе провайдера. Выбор сохраняется, если игрок переподключится до конца регистрации.
6. **Совпадение ника.** Аккаунт с ником игрока использует этого провайдера. Один только ник ничего не доказывает о клиенте.
7. **Обнаружение.** Провайдер узнаёт ник, но без доказательства.

При равных по силе причинах побеждает провайдер с большим `priority`. Победить могут только провайдеры, которые доступны прохождению: имя хоста провайдера, которого прохождение не предлагает, не учитывается, а провайдер, у которого вход игрока не удался, исключается до конца прохождения.

Что это значит на практике:

- Новый игрок, который заходит через имя хоста провайдера, регистрируется у этого провайдера. В интерактивном прохождении выбор провайдера пропускается, если провайдер имени хоста есть среди предложенных.
- Игрок, у подтверждённого входа которого уже есть аккаунт, сохраняет провайдера этого аккаунта, через какое бы имя хоста он ни зашёл. Аккаунт Premium остаётся у провайдера Premium и через имя хоста провайдера Credential.
- У нового игрока имя хоста побеждает подтверждённый вход без аккаунта. Владелец премиум-аккаунта, который заходит в бесшовной сети через имя хоста провайдера Credential и у которого запрашивают премиум-вход, потому что ник премиальный, всё равно регистрируется у провайдера Credential, и при следующих входах у него запрашивают пароль Credential. Через имя хоста провайдера Premium тот же игрок регистрируется у провайдера Premium.
- Если ник `Steve` занят аккаунтом Credential, настоящий владелец премиум-аккаунта `Steve`, который заходит через имя хоста провайдера Premium, проходит премиум-вход и попадает в свой собственный аккаунт Premium или регистрирует его. Без такого входа за провайдера говорит только совпадение ника, поэтому у игрока запрашивают пароль Credential.
