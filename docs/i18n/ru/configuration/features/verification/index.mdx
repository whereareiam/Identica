`features/verification/` содержит файлы верификации: `settings.yml`, `commands.yml` и `messages.yml`. Как ею пользуются игроки, описано в разделе [Верификация](../../../admins/features/verification/index.mdx).

## settings.yml

<Setting
  name="challengeTtl"
  takes="положительную длительность"
  default='`"2m"`'
  affects="сколько времени у игрока есть, чтобы ответить на запрос верификации"
>

Если значение слишком мало, медленные игроки теряют запрос; если слишком велико, неотвеченный запрос остаётся открытым дольше, чем нужно.

</Setting>

<Setting

  affects="сколько времени у игрока есть, чтобы подтвердить настройку метода"
>

</Setting>

<Setting
  name="autoSelectCurrentProvider"
  takes="`true` или `false`"
  default="`true`"
  affects="выбирается ли только что настроенный метод для провайдера, через которого игрок вошёл"

С `false` игроки выбирают его сами командой `/2fa use`.

### totp

Встроенный метод через приложение-аутентификатор. См. [Приложения-аутентификаторы](../../../admins/features/verification/authenticator-apps/index.mdx).

<Setting
  name="displayName"
  depth={4}
  takes="строку"
  default='`"Authenticator App"`'
  affects="название метода в сообщениях"
>

Если значение пустое, показывается `totp`.

</Setting>

<Setting
  name="issuer"
  depth={4}
  takes="строку"
  default='`"Identica"`'
  affects="название сервиса, которое приложения-аутентификаторы показывают для аккаунта"
>

</Setting>

<Setting
  name="labelFormat"
  depth={4}
  takes="строку"
  default='`"{player}@{providerId}"`'
  affects="имя аккаунта, которое показывают приложения-аутентификаторы"
>

`{player}` — ник игрока, `{providerId}` — провайдер, через которого он настроил приложение.

</Setting>

<Setting
  name="digits"
  depth={4}
  takes="целое число"
  default="`6`"
  affects="сколько цифр в коде"
  flag="advanced"
>

Уже настроенные приложения сохраняют прежнее число цифр, поэтому после изменения игроки не смогут войти, пока не настроят приложение заново.

</Setting>

<Setting
  name="period"
  depth={4}
  takes="положительную длительность"
  default='`"30s"`'
  affects="как часто меняются коды"
  flag="advanced"
>

Как и `digits`, изменение не доходит до уже настроенных приложений.

</Setting>

<Setting
  name="allowedPastWindows"
  depth={4}
  takes="целое число"
  default="`1`"
  affects="сколько предыдущих кодов ещё принимается — для телефонов, у которых отстают часы, и для медленного ввода"
  flag="advanced"
>

Чем больше окон, тем терпимее проверка, но тем дольше принимаются коды.

</Setting>

<Setting
  name="allowedFutureWindows"
  depth={4}
  takes="целое число"
  default="`1`"
  affects="сколько следующих кодов уже принимается — для телефонов, у которых спешат часы"
  flag="advanced"
>

При любых окнах каждый код принимается один раз: после того как код принят, коды его окна и более ранних окон для этого аккаунта отклоняются. Поэтому игрок, у которого приложение спешит и который ввёл код будущего окна, ждёт окна после него, прежде чем следующий код будет принят.

</Setting>

### defaults

Политика для каждого провайдера, который не задаёт собственную. См. [Политика для отдельных провайдеров](../../../admins/features/verification/provider-policy/index.mdx).

```yaml
defaults:
  enabled: true
  required: false
  unavailableSelectionPolicy: KEEP_LOCKED
  methods:
    - id: totp
      enabled: true
      priority: 100
```

Поля те же, что в настройках для отдельного провайдера ниже.

## Для отдельного провайдера [#per-provider]

В `features.verification` записи провайдера в `providers/providers.yml`. Каждое поле, которое провайдер не указывает, берётся из `defaults`.

<Setting
  name="features.verification.enabled"
  takes="`true` или `false`"
  default="наследует `defaults.enabled` (`true`)"
  affects="могут ли игроки этого провайдера пользоваться верификацией"
>

</Setting>

<Setting
  name="features.verification.required"
  takes="`true` или `false`"
  default="наследует `defaults.required` (`false`)"
  affects="обязаны ли игроки этого провайдера пользоваться верификацией"
>

Тогда игроку без метода отказывают при входе.

</Setting>

<Setting
  name="features.verification.unavailableSelectionPolicy"
  takes='`"CLEAR_SELECTION"` или `"KEEP_LOCKED"`'
  default="наследует `defaults.unavailableSelectionPolicy` (`KEEP_LOCKED`)"
  affects="сохраняется ли выбранный игроком метод, когда провайдер его больше не предлагает"
>

`KEEP_LOCKED` сохраняет его, `CLEAR_SELECTION` забывает. В обоих случаях, пока верификация обязательна, во входе отказывают.

</Setting>

<Setting
  name="features.verification.methods"
  takes="список методов"
  default="наследует `defaults.methods`"
  affects="какие методы предлагает этот провайдер и в каком порядке"
>

Явно заданный `methods: []` не предлагает ни одного. У каждого метода есть поля:

- `id`: id метода верификации, например `totp`
- `enabled`: можно ли использовать этот метод
- `priority`: порядок, если доступно несколько методов
- `required`: собственное `required` этого метода вместо значения провайдера
- `unavailableSelectionPolicy`: собственная политика этого метода вместо политики провайдера

</Setting>

## commands.yml и messages.yml [#commandsyml-and-messagesyml]

У команд игроков, например `/2fa enroll`, и у `/identica admin 2fa reset` те же поля, что и в [`commands.yml`](../../commands/index.mdx#commands). Коды восстановления показываются, даже если их сообщение очищено, потому что показать их повторно нельзя.
