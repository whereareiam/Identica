Верификация добавляет второй шаг после того, как провайдер определил игрока. Например, игрок входит со своим паролем, а затем у него запрашивается код, который показывает его приложение-аутентификатор. Вход завершается только после того, как код принят.

## Что делают игроки [#what-players-do]

Игроки настраивают верификацию сами — командами, которые доступны после входа:

| Команда | Что делает |
| --- | --- |
| `/2fa` | показывает команды верификации |
| `/2fa status` | показывает, какие методы настроены |
| `/2fa enroll totp` | начинает настройку приложения-аутентификатора |
| `/2fa enroll confirm <code>` | завершает настройку первым кодом |
| `/2fa enroll cancel` | отменяет настройку |
| `/2fa confirm <code>` | отвечает на запрос верификации во время входа |
| `/2fa use <provider> <method>` | выбирает, какой метод запрашивает провайдер |
| `/2fa disable <method>` | отключает метод |

Отключение метода — защищённое действие: игрок тоже подтверждает его кодом. Игроку, потерявшему доступ, персонал сбрасывает верификацию командой `/identica admin 2fa reset`; см. [Управление аккаунтами](../../guides/accounts/managing-accounts/index.mdx#two-factor-verification).

Встроенный метод — [приложение-аутентификатор](./authenticator-apps/index.mdx) с кодами восстановления для игроков, которые его потеряли. Аддоны могут добавлять другие методы.

## Необязательная или обязательная [#optional-or-required]

По умолчанию верификация предлагается игрокам всех провайдеров, но не обязательна: у игрока, который её настроил, она запрашивается, а все остальные входят как раньше. Провайдер может сделать её обязательной, чтобы его игроки не могли войти без неё, или не предлагать её вовсе; см. [Политика для провайдеров](./provider-policy/index.mdx).

## Коды одноразовые [#codes-are-used-once]

Каждый код аутентификатора принимается для аккаунта один раз — подтверждает ли он вход или защищённое действие; код, которым была подтверждена настройка, тоже считается использованным. После того как код принят, коды его временного окна и более ранних окон отклоняются на всех прокси, которые используют общую базу данных, и игрок вводит следующий код. На отклонённый код игрок получает тот же ответ, что и на неверный. Коды восстановления тоже одноразовые.

Все настройки описаны на странице [Настройки верификации](../../../configuration/features/verification/index.mdx).
