`routing.yml` задаёт серверы, на которые отправляются игроки, пока вход ждёт их (`step`), и после того, как они вошли (`complete`). Руководство [Маршрутизация игроков](../../admins/guides/network/routing/index.mdx) объясняет их на примерах.

У каждой цели одинаковые поля: `target`, `forcedHosts` и `attempts`.

## defaults

Цели для каждого сценария, который не задаёт собственных.

<Setting
  name="step"
  takes="цель"
  default='`"auth"`'
  affects="то, куда игрок попадает, пока вход ждёт от него ответа, например пароля"
>

Если цель пуста и цели сценария тоже нет, игрок остаётся там, где находится.

</Setting>

<Setting
  name="complete"
  takes="цель"
  default='`"survival"`'
  affects="то, куда игрок попадает после завершения входа"
>

Если цель пуста и цели сценария тоже нет, игрок остаётся там, где находится. Игрок, завершивший вход ещё во время подключения, получает сообщения о завершении на первом сервере, на который попадёт.

</Setting>

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
defaults:
  step:
    target: "auth"
  complete:
    target: "survival"
    forcedHosts: false
scenarios: {}
```
  </Tab>
  <Tab value="JSON">
```json
{
  "defaults": {
    "step": {
      "target": "auth"
    },
    "complete": {
      "target": "survival",
      "forcedHosts": false
    }
  },
  "scenarios": {}
}
```
  </Tab>
</Tabs>

## Поля цели [#target-fields]

<Setting
  name="target"
  takes='имя сервера из конфигурации прокси или `""`'
  affects="то, на какой сервер отправляется игрок"
>

Сервер, которого прокси не знает, отключает игрока с сообщением [`routing.missingServer`](../messages/index.mdx#routing).

</Setting>

<Setting
  name="forcedHosts"
  takes="`true` или `false`"
  default="`false` в `defaults.complete`; в остальных местах — значение менее конкретной цели"
  affects="то, отправляется ли игрок на сервер, который прокси закрепляет за хостнеймом, через который он зашёл"
>

`target` используется для хостнеймов без закреплённого сервера (forced host). Если в Velocity для хостнейма указано несколько серверов, используется первый. См. [Хостнейм игрока](../../admins/guides/network/routing/index.mdx#the-players-hostname).

</Setting>

### attempts

Сколько раз Identica пытается переместить игрока, если сервер его не пускает. См. [Когда сервер не пускает игрока](../../admins/guides/network/routing/index.mdx#when-a-server-turns-the-player-away).

<Setting
  name="mode"
  depth={4}
  takes='`"NONE"`, `"RETRY_ONCE"`, `"RETRY_LIMITED"` или `"UNTIL_REACHED"`'
  affects="то, сколько делается попыток"
  flag="advanced"
>

| Режим | Попытки |
| --- | --- |
| `NONE` | одна |
| `RETRY_ONCE` | две |
| `RETRY_LIMITED` | `maxAttempts` |
| `UNTIL_REACHED` | пока сервер не пустит игрока |

</Setting>

<Setting
  name="maxAttempts"
  depth={4}
  takes="целое число"
  affects="число попыток в режиме `RETRY_LIMITED`"
  flag="advanced"
>

Другие режимы его не учитывают.

</Setting>

<Setting
  name="retryDelay"
  depth={4}
  takes="длительность"
  default='`"0s"`'
  affects="паузу перед следующей попыткой"
  flag="advanced"
>

</Setting>

<Setting
  name="consumeOnReached"
  depth={4}
  takes="`true` или `false`"
  affects="то, забывает ли Identica маршрут, как только игрок попал на сервер"
  flag="advanced"
>

При `false` Identica хранит маршрут, пока его не заменит следующий.

</Setting>

<Setting
  name="consumeOnExhausted"
  depth={4}
  takes="`true` или `false`"
  affects="то, забывает ли Identica маршрут, когда его попытки исчерпаны"
  flag="advanced"
>

При `false` Identica хранит неудавшийся маршрут, пока его не заменит следующий.

</Setting>

<Setting
  name="scenarios"
  depth={2}
  takes="словарь с ключами `authentication`, `registration` или `migration` в любом регистре"
  default="`{}`"
  affects="цели `step` и `complete` одного сценария"
>

Добавляйте сценарий, только если он должен отличаться от `defaults`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
scenarios:
  registration:
    step:
      target: "register"
    complete:
      target: "tutorial"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "scenarios": {
    "registration": {
      "step": {
        "target": "register"
      },
      "complete": {
        "target": "tutorial"
      }
    }
  }
}
```
  </Tab>
</Tabs>

</Setting>

<Setting
  name="overrides.stages"
  takes="словарь, ключами которого служат идентификаторы этапов, например `provider`"
  affects="цель `step`, пока игрок ждёт на этом этапе сценария"
  flag="advanced"
>

</Setting>

<Setting
  name="overrides.steps"
  takes="словарь, ключами которого служат имена шагов, например `enrollment`"
  affects="цель `step`, пока игрок ждёт на этом шаге"
  flag="advanced"
>

Переопределение шага важнее переопределения этапа.

</Setting>

```yaml
scenarios:
  registration:
    overrides:
      stages:
        provider:
          target: "register-fallback"
      steps:
        enrollment:
          target: "choose-provider"
```
