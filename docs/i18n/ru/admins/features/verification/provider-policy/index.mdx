Запрашивается ли у игроков провайдера верификация и какими методами — это политика. Общая политика задаётся в `defaults` в `features/verification/settings`:

```yaml
defaults:
  enabled: true
  required: false
  unavailableSelectionPolicy: KEEP_LOCKED
  methods:
    - id: totp
      enabled: true
      priority: 100
```

- `enabled`: могут ли игроки провайдера вообще пользоваться верификацией.
- `required`: обязаны ли игроки провайдера пользоваться верификацией. При `false` она необязательна.
- `methods`: методы, которые предлагает провайдер, в порядке `priority`. Явный `methods: []` не предлагает ни одного.
- `unavailableSelectionPolicy`: что происходит с выбранным игроком методом, когда провайдер его больше не предлагает. Пока верификация обязательна, вход отклоняется, а если необязательна — продолжается без неё. `KEEP_LOCKED` сохраняет выбор игрока, и метод снова запрашивается, как только его опять предложат; `CLEAR_SELECTION` сбрасывает выбор.

## Разные политики для провайдеров [#different-policies-per-provider]

Запись провайдера в `providers/providers.yml` переопределяет только то, что в ней указано; остальное берётся из `defaults`:

```yaml
providers:
  - id: "credential"
    features:
      verification:
        required: true
  - id: "premium"
    features:
      verification:
        enabled: false
```

Здесь каждый игрок Credential обязан пользоваться верификацией, а у игроков Premium она никогда не запрашивается. Лицензионные аккаунты уже защищены входом через Mojang, поэтому многие сети требуют верификацию только для провайдеров с паролем.

<Callout type="warn" title="Обязательная — значит без неё вход отклоняется">
  При `required: true` игрок этого провайдера, который не настроил ни одного метода, получает отказ при входе с сообщением `scenario.authentication.verification.required` из `messages.yml` провайдера. Игроки настраивают верификацию, когда уже вошли, поэтому попросите их настроить её до того, как сделаете её обязательной.
</Callout>

Запись метода может также задать `required` или `unavailableSelectionPolicy` только для этого метода.

## Защищённые действия [#protected-actions]

Такие действия, как отключение метода, запрашивают верификацию согласно политике провайдера, через который игрок вошёл. Переход на другой провайдер не позволяет её обойти.

Все поля описаны на странице [Настройки верификации](../../../../configuration/features/verification/index.mdx#per-provider).
