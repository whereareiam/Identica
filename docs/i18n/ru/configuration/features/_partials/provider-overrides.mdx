Переопределения для провайдера задаются внутри записи провайдера, в объекте `features`.
Если провайдеру нужно особое поведение, добавьте поддерево, описанное в справке по функции. Блоки переопределений для распознавания и ограничения входа не создаются только потому, что провайдер заявляет соответствующую интеграцию.

Для общих настроек, которые поддерживают переопределения, пропущенные поля наследуют общие значения. Поля с другими значениями по умолчанию или особыми правилами участия описаны в справке по каждой функции — в том числе по верификации.

Например:

```yaml
providers:
  - id: "credential"
    features:
      recognition:
        enabled: true
      restriction:
        join:
          enabled: true
          allow:
            - linked
            - recognized
```

Эти переопределения действуют для функций, которые провайдер заявляет в `supportedFeatures()`. Все реализации встроены в Identica.
