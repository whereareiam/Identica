`providers/providers.yml` enables providers and sets their order, their hostnames, and their own session and feature settings. Each provider's own settings are in its folder next to this file. [How a provider is picked](../../admins/guides/logins/provider-selection/index.mdx) explains how the order and the hostnames are used.

## behavior

<Setting
  name="attemptTtl"
  takes="a positive duration"
  default='`"10m"`'
  affects="how long Identica remembers that a provider was already tried for a username and address"
  flag="advanced"
>

A player whose premium login failed, for example an offline client with a premium username, continues with the next provider when they join again from the same address within this time. Longer values keep that choice longer; shorter ones let the provider be tried again sooner.

</Setting>

<Setting
  name="providers"
  depth={2}
  takes="a list of provider entries"
  affects="which providers are loaded, and how each one takes part"
>

Identica loads a provider only when it has an entry here with `enabled: true`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
behavior:
  attemptTtl: "10m"
providers:
  - id: "premium"
    displayName: "Premium"
    enabled: true
    priority: 100
    entrypoints:
      - "premium.example.com"
    session:
      concurrencyPolicy: "REJECT_NEW"
  - id: "credential"
    displayName: "Credential"
    enabled: true
    priority: 50
    entrypoints:
      - "credential.example.com"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "behavior": {
    "attemptTtl": "10m"
  },
  "providers": [
    {
      "id": "premium",
      "displayName": "Premium",
      "enabled": true,
      "priority": 100,
      "entrypoints": ["premium.example.com"],
      "session": {
        "concurrencyPolicy": "REJECT_NEW"
      }
    },
    {
      "id": "credential",
      "displayName": "Credential",
      "enabled": true,
      "priority": 50,
      "entrypoints": ["credential.example.com"]
    }
  ]
}
```
  </Tab>
</Tabs>

</Setting>

<Setting
  name="id"
  takes="a provider id, such as `premium` or `credential`, in any case"
  affects="which installed provider the entry configures"
>

</Setting>

<Setting
  name="displayName"
  takes="a string"
  default='`""`'
  affects="the provider's name in messages to players, such as the provider choice"
>

A blank name uses the provider's own name.

</Setting>

<Setting
  name="enabled"
  takes="`true` or `false`"
  affects="whether the provider is loaded and offered to players"
>

</Setting>

<Setting
  name="priority"
  takes="an integer"
  affects="which provider wins when several have an equally strong reason to handle a player"
>

Higher values win.

</Setting>

<Setting
  name="entrypoints"
  takes="a list of hostnames, as `host` or `host:port`"
  affects="which hostnames pick this provider for a joining player"
>

A `host` entry matches the hostname on any port; `host:port` only on that port. When several providers list a hostname, the one with the higher `priority` takes it. Leave the list empty when your players all join through one address. See [Hostnames](../../admins/guides/logins/provider-selection/index.mdx#hostnames).

</Setting>

<Setting
  name="methods"
  takes="an object with an `authentication`, `registration` or `migration` list of method names"
  default="absent"
  affects="which of the provider's methods each scenario offers, and in which order"
  flag="advanced"
>

Only for a provider that offers several ways to get a scenario done, such as a quick check and a guided setup; its own documentation names them. A scenario left out offers all of them in the provider's order. A listed scenario offers only the methods it names, in that order:

```yaml
methods:
  migration: ["guided", "quick"]
```

With [`choice: "AUTOMATIC"`](../engine/index.mdx#choice) the first method that can finish the login is used; with `"PROMPTED"` the player sees each listed method as an option. See [Provider choice](../../admins/guides/logins/provider-choice/index.mdx#a-providers-methods).

</Setting>

<Setting
  name="session.concurrencyPolicy"
  takes='`"REPLACE_EXISTING"` or `"REJECT_NEW"`'
  default="absent"
  affects="what happens when an account of this provider logs in from a second connection"
  flag="advanced"
>

When absent, the provider follows [`sessions.concurrencyPolicy`](../settings/index.mdx#concurrencypolicy) of `settings.yml`.

</Setting>

<Setting
  name="features"
  takes="an object with one entry per feature"
  default="absent"
  affects="this provider's own settings for a feature"
>

Whatever an entry leaves out comes from the feature's shared settings. The provider must support the feature; turning on a feature the provider does not support stops the provider from loading.

| Key | Page |
| --- | --- |
| `features.recognition` | [Recognition](../features/recognition/index.mdx#per-provider) |
| `features.restriction.enabled` | [Restriction](../features/restriction/index.mdx#per-provider) |
| `features.restriction.join` | [Join restriction](../features/restriction/join/index.mdx#per-provider) |
| `features.sentinel.enabled` | [Sentinel](../features/sentinel/index.mdx#per-provider) |
| `features.verification` | [Verification](../features/verification/index.mdx#per-provider) |

See [Features](../../admins/features/index.mdx#on-for-everyone-or-per-provider).

</Setting>
