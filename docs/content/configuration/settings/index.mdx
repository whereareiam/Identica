`settings.yml` holds the logging level, how accounts get their UUIDs, the session policy, and the proxy listeners.

<Setting
  name="level"
  depth={2}
  takes="an integer from `0` to `4`"
  default="`2`"
  affects="how much Identica writes to the console"
>

| Value | Writes |
|-------|----------------------------|
| `0`   | errors only                |
| `1`   | warnings and errors        |
| `2`   | info, warnings, and errors |
| `3`   | adds debug logging         |
| `4`   | adds trace logging         |

Use `2` for normal operation and `3` or `4` while you look into a problem.

</Setting>

## identity

<Setting
  name="uniqueIdMode"
  takes='`"RANDOM"`, `"OFFLINE"`, or `"PREMIUM"`'
  default='`"RANDOM"`'
  affects="how new accounts get their UUID"
  flag="danger"
>

`RANDOM` gives each account a new random UUID, `OFFLINE` the offline-mode UUID of its username, `PREMIUM` its premium UUID. Existing accounts keep their UUID. See [Unique ids](../../admins/guides/accounts/unique-ids/index.mdx) before changing it.

</Setting>

<Setting
  name="reservationTtl"
  takes="a positive duration"
  default='`"15m"`'
  affects="how long a reserved UUID waits for an account to be registered under its username"
  flag="advanced"
>

A reservation made with `/identica admin reservation set`, with `/identica admin clear`, or while a registration is in progress expires after this time if nobody registers under the username. Too short, and a slow registration loses its reserved UUID; too long, and abandoned reservations stay around longer.

</Setting>

## sessions

<Setting
  name="concurrencyPolicy"
  takes='`"REPLACE_EXISTING"` or `"REJECT_NEW"`'
  default='`"REPLACE_EXISTING"`'
  affects="what happens when an account that has a session logs in from another connection"
  flag="warning"
>

`REPLACE_EXISTING` disconnects the earlier connection; `REJECT_NEW` refuses the new login. Any other value stops the startup with an error that names the accepted values. A provider can use another policy with `session.concurrencyPolicy` in [`providers/providers.yml`](../providers/index.mdx#sessionconcurrencypolicy). See [Sessions](../../admins/guides/logins/sessions/index.mdx).

</Setting>

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
level: 2
identity:
  uniqueIdMode: "RANDOM"
  reservationTtl: "15m"
sessions:
  concurrencyPolicy: "REPLACE_EXISTING"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "level": 2,
  "identity": {
    "uniqueIdMode": "RANDOM",
    "reservationTtl": "15m"
  },
  "sessions": {
    "concurrencyPolicy": "REPLACE_EXISTING"
  }
}
```
  </Tab>
</Tabs>

## listeners

Identica follows the proxy's events to handle joining players. `listeners.events` lets you change the priority of one of these listeners, for example to run before or after another plugin that handles the same event, or to leave it out.

<Setting
  name="events"
  takes="a map keyed by the proxy event's full class name"
  affects="whether Identica listens to that event, and with which priority"
  flag="advanced"
>

<ContentTabs items={["Velocity", "BungeeCord"]}>
  <ContentTab value="Velocity">
```yaml
listeners:
  events:
    com.velocitypowered.api.event.connection.PreLoginEvent:
      register: true
      priority: "NORMAL"
```
  </ContentTab>
  <ContentTab value="BungeeCord">
```yaml
listeners:
  events:
    net.md_5.bungee.api.event.PlayerHandshakeEvent:
      register: true
      priority: "NORMAL"
```
  </ContentTab>
</ContentTabs>

</Setting>

<Setting
  name="register"
  takes="`true` or `false`"
  affects="whether Identica listens to the event at all"
  flag="warning"
>

Turning a listener off breaks the part of the login that depends on it. Only do it when another plugin takes over that event's work.

</Setting>

<Setting
  name="priority"
  takes='`"LOWEST"`, `"LOW"`, `"NORMAL"`, `"HIGH"`, or `"HIGHEST"`'
  default='`"NORMAL"`'
  affects="when Identica's listener runs compared to other plugins' listeners of the same event, in the proxy's own priority order"
  flag="advanced"
>

</Setting>
