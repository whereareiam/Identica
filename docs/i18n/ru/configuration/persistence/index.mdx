Конфигурация хранения данных определяет, какую базу данных использует Identica и как настроен пул подключений.

Если файла ещё нет или в нём не задан `type`, Identica использует SQLite.

Identica создаёт свои таблицы при первом запуске и обновляет их при последующих — после обновления самой Identica, функции или провайдера. Сведения о том, до какой версии дошёл каждый набор таблиц, хранятся в таблице `strata_history`; не трогайте её. Если несколько прокси используют одну базу данных, она обновляется один раз: это делает прокси, запустившийся первым, а остальные ждут.

## type

- Принимает: `"SQLITE"`, `"H2"`, `"MYSQL"` или `"POSTGRES"`
- По умолчанию: `"SQLITE"`
- Значения чувствительны к регистру. Любое другое значение останавливает запуск с ошибкой, в которой указаны `type`, само значение и допустимые значения; файл при этом не меняется. Поскольку при неудачном запуске отклоняются все подключения, Identica никогда не работает с базой данных, которая не указана в файле.
- Влияет на: класс хранилища и способ построения JDBC URL

`"MYSQL"` работает с MySQL 8.0.19 и новее, а также с MariaDB.

## Поля для конкретных баз данных [#backend-specific-fields]

У разных типов хранилища свои поля.
Обычно они появляются в файле после того, как вы смените `type` и перезапустите плагин.
Если только изменить `type` и не дать плагину запуститься снова, структура файла может соответствовать старому типу базы данных, пока Identica не создаст его заново.

    #### file

    - Принимает: имя файла, относительный путь или прямой адрес H2

    - Влияет на: базу данных H2, к которой подключается Identica

    - По умолчанию: `""`
    - Влияет на: параметры JDBC для H2, добавляемые к URL подключения

    Если параметры заданы, Identica добавляет их к базовому URL H2 и при необходимости сама вставляет `;`.
  </ContentTab>

    - Нужна MySQL 8.0.19 или новее.     - Минимальной версии MariaDB Identica не требует.

    - Принимает: строку
    - По умолчанию: `"localhost"`
    - Влияет на: хост сервера базы данных

    - Принимает: целое число
    - По умолчанию: `3306`
    - Влияет на: порт сервера базы данных

    #### database

    - Принимает: строку
    - По умолчанию: `"identica"`
    - Влияет на: имя базы данных в JDBC URL

    #### username

    - Принимает: строку
    - По умолчанию: `"identica"`
    - Влияет на: имя пользователя для подключения к внешней базе данных

    #### credential

    - Принимает: строку
    - По умолчанию: `""`
    - Влияет на: пароль для подключения к внешней базе данных

## hikari

Раздел `hikari` настраивает пул подключений HikariCP, через который работает слой базы данных.

В большинстве случаев значения по умолчанию — хорошая отправная точка.
Обычно их меняют, только когда для этого есть конкретная причина: нагрузка на базу данных, ограничения на число подключений или тонкая настройка инфраструктуры.

#### poolName

<Badge type="warning">Для опытных</Badge>

- Принимает: строку
- По умолчанию: `"Identica"`
- Влияет на: имя пула Hikari, которое отображается в диагностике и логах

#### maximumPoolSize

<Badge type="warning">Для опытных</Badge>

- Принимает: целое число
- По умолчанию: `10`
- Влияет на: максимальное число подключений к базе данных в пуле

#### minimumIdle

<Badge type="warning">Для опытных</Badge>

- Принимает: целое число
- По умолчанию: `2`
- Влияет на: минимальное число простаивающих подключений, которые Hikari старается держать наготове

#### connectionTimeout

<Badge type="warning">Для опытных</Badge>

- Принимает: число миллисекунд
- По умолчанию: `30000`
- Влияет на: сколько Hikari ждёт свободного подключения, прежде чем прервать ожидание по тайм-ауту

#### idleTimeout

<Badge type="warning">Для опытных</Badge>

- Принимает: число миллисекунд
- По умолчанию: `600000`
- Влияет на: сколько подключение в пуле может простаивать, прежде чем Hikari его закроет

#### maxLifetime

<Badge type="warning">Для опытных</Badge>

- Принимает: число миллисекунд
- По умолчанию: `1800000`
- Влияет на: максимальное время жизни подключения в пуле, после которого Hikari заменяет его новым

## Поведение при подключении [#connection-behavior]

Если подключиться к базе данных не удаётся, Identica не завершает работу сразу при инициализации Hikari.
Вместо этого она записывает проблему с подключением в лог, а функции, которым нужна база данных, остаются недоступны, пока подключение не будет установлено.
