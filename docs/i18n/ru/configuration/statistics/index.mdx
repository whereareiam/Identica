Identica отправляет анонимную статистику использования в [bStats](https://bstats.org/plugin/velocity/Identica/30854) и [FastStats](https://faststats.dev), а также сообщает FastStats о своих ошибках.
По этим данным видно, какие конфигурации используются и какие ошибки возникают, — так баги можно исправлять, не прося никого присылать логи.

Оба сервиса настраиваются вне Identica, в файлах, общих для всех плагинов, которые ими пользуются.
При первом запуске прокси с FastStats ничего не отправляется: в этот раз FastStats только создаёт свой файл.

## Отключение статистики [#turn-statistics-off]

| Сервис | Файл | Настройка |
| --- | --- | --- |
| bStats | `plugins/bStats/config.txt` | `enabled=false` |
| FastStats | `plugins/faststats/config.properties` | `enabled=false` отключает всё, `submitErrors=false` — только отчёты об ошибках |

После изменения файла перезапустите прокси.
С отключённой статистикой Identica работает точно так же.

## Что отправляется [#what-is-sent]

Каждые 30 минут каждый сервис получает:

| Статистика | Значения |
| --- | --- |
| `providers` | включённые провайдеры: `credential`, `premium` и `custom` для любых других |
| `features` | функции, включённые хотя бы для одного провайдера, например `verification` |
| `verification_methods` | зарегистрированные встроенные способы подтверждения и `custom` для любых других |
| `persistence_type`, `replication_type` | тип базы данных и включена ли репликация через Redis |
| `unique_id_mode`, `session_concurrency` | значения [`uniqueIdMode`](../settings/index.mdx#uniqueidmode) и [`concurrencyPolicy`](../settings/index.mdx#concurrencypolicy) |
| `authentications`, `registrations`, `migrations` | сколько их завершилось с момента прошлой отправки, по результату: `completed`, `failed`, `denied`, `cancelled`, `expired` |
| `logins_by_provider` | успешные входы с момента прошлой отправки, по провайдерам: `credential`, `premium` и `custom` для любых других |
| `sessions_opened` | сколько сессий открыто с момента прошлой отправки |
| `client_versions` | игроки, находящиеся на прокси, в разбивке по версии Minecraft их клиента |
| `account_count`, `provider_usage` | сколько аккаунтов хранится — всего и по провайдерам |
| `verified_accounts` | у скольких аккаунтов включён способ подтверждения, например TOTP |

Сервисы также добавляют данные, которые собирают со всех плагинов: версию прокси, число игроков, версию Java, операционную систему и т. п.

Если несколько прокси используют одну базу данных, `account_count`, `provider_usage` и `verified_accounts` отправляет только один из них, чтобы аккаунты не учитывались повторно для каждого прокси.
Прокси договариваются об этом через таблицу `identica_statistics_lease`; когда этот прокси останавливается, его роль берёт на себя другой.

## Что не отправляется никогда [#what-is-never-sent]

- ники игроков, уникальные идентификаторы, IP-адреса, пароли и всё остальное, что вводил игрок
- имена серверов, имена хостов, адреса и другие значения из вашей конфигурации
- идентификатор или название провайдера, функции или способа подтверждения, которые не входят в Identica

## Отчёты об ошибках [#error-reports]

Когда Identica записывает в лог ошибку, вызванную багом в её собственном коде или в официальных провайдерах, FastStats получает тип ошибки, её сообщение и стек вызовов, а также сообщение лога, к которому она относится.
Перед тем как данные покинут прокси:

- из сообщений ошибки удаляются ники игроков, уникальные идентификаторы и другие значения из сообщения лога
- скрываются уникальные идентификаторы, адреса электронной почты, IP-адреса и значения, которые база данных подставляет в свои сообщения об ошибках
- ошибки сторонних провайдеров и других плагинов не отправляются
- недоступная база данных или Redis, а также отказ в доступе по учётным данным не отправляются, потому что это проблема настройки

Отправляется не более 100 ошибок за 30 минут.
