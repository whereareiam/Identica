Сценарий часто можно пройти несколькими путями. Каждый включённый провайдер — это один вариант, а провайдер может предлагать и несколько собственных способов, например быструю проверку и пошаговую настройку. Кто выбирает среди вариантов — Identica или игрок, — решает `choice` в каждом сценарии `engine.yml`.

| Сценарий | По умолчанию |
| --- | --- |
| аутентификация | `AUTOMATIC` |
| регистрация | `AUTOMATIC` |
| миграция | `AUTOMATIC` |

При любом значении игрока никогда не отключают из-за того, что ему нужно что-то ввести. Если выбранному провайдеру нужен пароль или код из приложения-аутентификатора, игрока просят его ввести.

## Значения [#choices]

<Tabs items={["AUTOMATIC", "PROMPTED"]}>
  <Tab value="AUTOMATIC">
    Выбирает Identica. Первым идёт провайдер, которого [порядок выбора](../provider-selection/index.mdx) ставит выше всех: тот, через чьё имя хоста зашёл игрок, затем тот, к которому привязан его аккаунт, затем провайдер с наибольшим приоритетом. Способы провайдера идут в своём порядке. Если вариант не может завершить вход, пробуется следующий. У игрока запрашивают только то, что нужно выбранному провайдеру.

    Это значение подходит сетям, провайдеры которых сами умеют различать игроков. Подвох в первом входе пиратского (офлайн) игрока под ником лицензионного аккаунта: провайдер Premium с более высоким приоритетом требует лицензионный вход прямо при рукопожатии, ещё до того, как игрок что-либо увидит. Клиент не может его пройти и отключается с ошибкой «недействительная сессия», и может показаться, что на сервер пускают только с лицензией. Следующий вход с того же адреса в пределах [`attemptTtl`](../../../../configuration/providers/index.mdx#attemptttl) продолжается со следующим провайдером.

    [Способ определения `CLIENT_PROFILE`](../../../providers/official/premium/detection/index.mdx) провайдера Premium позволяет избежать этого для клиентов версии 1.19.1 и новее.
  </Tab>
  <Tab value="PROMPTED">
    Игрок видит варианты и выбирает один из них — щелчком или командой `/identica enroll <option>`. Новый игрок, который заходит с офлайн-клиента под ником лицензионного аккаунта, выбирает провайдера сам, а не получает сразу требование лицензионного входа: если сценарий регистрации использует `PROMPTED`, проверка Premium при рукопожатии для ника без аккаунта пропускается.

    Игрока не спрашивают, когда выбирать не из чего:

    - остался только один вариант, например когда зарегистрировать игрока может только один провайдер;
    - игрок зашёл через [имя хоста](../provider-selection/index.mdx#hostnames) провайдера или его аккаунт привязан к провайдеру, и у этого провайдера один вариант. Если вариантов несколько, игрок выбирает только среди его способов.
  </Tab>
</Tabs>

```yaml
scenarios:
  registration:
    choice: "PROMPTED"
```

При миграции провайдера выбирает администратор, который её запускает, поэтому `PROMPTED` позволяет игроку выбирать только среди способов этого провайдера.

## Способы провайдера [#a-providers-methods]

Некоторые провайдеры предлагают для сценария несколько способов; они перечислены в документации самого провайдера. Каждый способ — отдельный вариант: при `PROMPTED` игрок видит его рядом с названием провайдера и выбирает его как `<provider>:<method>`, например `/identica enroll website:guided`.

`methods` в записи провайдера в `providers/providers.yml` убирает способы или меняет их порядок — отдельно для каждого сценария:

```yaml
providers:
  - id: "website"
    methods:
      migration: ["guided", "quick"]
```

См. [`methods`](../../../../configuration/providers/index.mdx#methods).

## Что видит игрок [#what-the-player-sees]

Варианты выводятся сообщением `engine.journey.step.enrollment` из `messages.yml`. Его `entryFormat` называет каждый вариант через `{optionName}`, а ответ — через `{optionId}`; `descriptions` может описывать отдельный вариант по его ID, например `website:guided`, или все варианты провайдера по ID провайдера.

Все настройки сценариев описаны в [`engine.yml`](../../../../configuration/engine/index.mdx).
