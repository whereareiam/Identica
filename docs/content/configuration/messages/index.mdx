This page documents only the shared message-formatting areas that affect many messages at once.
It does not try to explain every individual message field in the full messages configuration.

Feature-owned messages live in each feature's directory. Username synchronization failures and username conflict messages are configured in [identity/username/messages](../identity/username/index.mdx#messages).

## Formatting

Identica messages can use MiniMessage formatting.
If you want to use colors, decorations, click actions, hover actions, or other text formatting features, see the MiniMessage format reference here:

- [MiniMessage format reference](https://docs.papermc.io/adventure/minimessage/format/)

Identica also provides internal placeholders in some messages.
Those placeholders always use curly-brace format such as `{prefix}`, `{username}`, or `{provider}`.

The exact available placeholders depend on the specific message field and the code path that renders it.

## Emptying a message

A message set to an empty string, or a multi-line message set to an empty list, is not shown. That silences the text and changes nothing else: a player who is denied, locked out or disconnected is still denied, locked out or disconnected, with no reason shown.

Recovery codes are the exception, because they are shown once and cannot be read again: they are sent on their own when their message body is empty or does not contain `{entries}`.

## engine

The `engine` section holds messages of the login flow itself. Two of them belong to `settings.sessions.concurrencyPolicy`, which decides what happens when an account that is online logs in from another connection:

#### concurrentLoginKick

- Takes: a list of lines
- Affects: the reason shown to the earlier connection when `REPLACE_EXISTING` disconnects it, and to a connection that was still logging in when another connection logged in to the account

#### concurrentLoginRefused

- Takes: a list of lines
- Current default: a notice ending in `This account is already logged in.` and `Log out from the other location first.`
- Affects: the reason shown to the new login when `REJECT_NEW` refuses it because the account is already online

Emptying either message changes only the text. The earlier connection is still disconnected, and the new login is still refused, then with the scenario's general failure message.

#### usernameHeld

- Takes: a list of lines
- Current default: a notice reading `This name is being logged in from another location.` and `Try again shortly.`
- Affects: the reason shown to a connection that is refused because another connection, from another address, is logging in under the same username on another proxy of the network

See [Logins in progress](../engine/index.mdx#logins-in-progress) for when Identica refuses such a connection. Emptying the message changes only the text; the connection is still refused.

## routing

Identica disconnects a player when the server it routes them to does not exist on the proxy. The reason comes from the scenario the player is in, and from the shared message when that scenario has none.

#### routing.missingServer

- Takes: a list of lines
- Current default: a notice reading `No target server available for routing` and `Please contact a server administrator.`
- Affects: the reason shown when a routing target server is missing and the player's scenario has no message of its own, or the route belongs to no scenario

#### scenarios.authentication.routing.missingServer, scenarios.registration.routing.missingServer, scenarios.migration.routing.missingServer

- Takes: a list of lines
- Current default: `[]`
- Affects: the reason shown to a player in that scenario when a routing target server is missing

An empty scenario message shows `routing.missingServer` instead. To disconnect without a reason, empty both.

## prefix

- Takes: a string
- Current default: `"<green>Identica</green> <dark_gray>| "`
- Affects: the global message prefix supplied to the serializer engine

This prefix is available to messages through `{prefix}` and is also used as the serializer prefix supplier.

Changing this lets you rebrand or restyle the general look of Identica messages without editing every message line one by one.

## format

The `format` section controls shared formatting helpers used by message placeholders.

### temporal

The `temporal` subsection controls how shared date and date-time placeholders are formatted when messages render timestamps.

#### date

- Takes: a date-time pattern string
- Current default: `"dd.MM.yyyy"`
- Affects: the formatter pattern used for date-only placeholders

If this is blank, runtime code falls back to its built-in formatter for the specific message path.

#### dateTime

- Takes: a date-time pattern string
- Current default: `"dd.MM.yyyy HH:mm:ss"`
- Affects: the formatter pattern used for date-time placeholders

If this is blank, runtime code falls back to its built-in formatter for the specific message path.

## commands.pagination

The `commands.pagination` section controls the shared pagination renderer used by command outputs that span multiple pages.

These settings affect the formatting of page navigation, not which data is paginated.

#### showPaginationIfOnePage

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether pagination controls are shown when there is only one page

#### format

- Takes: a string
- Current default: `"\n {previous}<white>Pagination</white> <gray>[{current}/{max}]</gray>{next} \n"`
- Affects: the overall pagination line format

The pagination renderer can supply placeholders such as:

- `{previous}`
- `{next}`
- `{current}`
- `{max}`

#### showPreviousEvenIfFirst

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the previous-page control is still shown on the first page

#### previousTagFormat

- Takes: a string
- Current default: `"<red><click:run_command:/identica help {previousPage}>«</red> "`
- Affects: the rendered previous-page control

The pagination renderer can supply `{previousPage}` here.

#### showNextEvenIfLast

- Takes: `true` or `false`
- Current default: `false`
- Affects: whether the next-page control is still shown on the last page

#### nextTagFormat

- Takes: a string
- Current default: `" <green><click:run_command:/identica help {nextPage}>»</green>"`
- Affects: the rendered next-page control

The pagination renderer can supply `{nextPage}` here.
