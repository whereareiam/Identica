Откройте сгенерированную конфигурацию `providers/providers` и возьмите сгенерированную структуру за основу.
Чаще всего значения по умолчанию уже близки к тому, что вам нужно.

В типичных смешанных конфигурациях разумно дать `premium` более высокий приоритет, чем `credential`.
На практике это значит, что если у Identica есть одинаково сильные причины выбрать для игрока любой из этих провайдеров, `premium` побеждает раньше `credential`.
Именно такого поведения ожидает большинство пользователей.

На первом этапе важно решить:

- какие провайдеры остаются включёнными
- какой провайдер получает более высокий приоритет
- должен ли игрок получать провайдера по имени хоста, через которое заходит (`entrypoints`)

Практичная отправная точка выглядит так:

```yaml
behavior:
  attemptTtl: 10m

providers:
  - id: premium
    displayName: "PR"
    enabled: true
    priority: 200
    entrypoints:
      - premium.example.com

  - id: credential
    displayName: "CR"
    enabled: true
    priority: 100
    entrypoints:
      - credential.example.com
```

В большинстве установок значения `behavior` верхнего уровня на первом этапе можно не трогать.
