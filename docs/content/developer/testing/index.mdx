---
title: Live tests
description: Run and write player journeys against the packaged plugin on a real proxy.
---

The `identica-testing` module starts the packaged plugin and providers on a real Velocity proxy with Paper backends and drives simulated players through them with [Anvil](https://github.com/whereareiam/anvil). Unit tests stay in their own modules; these tests cover what a player experiences when joining.

## Run the tests

Run from the repository root; a Java 21 must be installed on the machine:

```shell
./gradlew :identica-testing:anvilTest
```

The task builds the plugin and provider jars, downloads the proxy and server distributions on first use, and starts a fresh proxy for every test. The first run takes several minutes; later runs reuse the downloads and Identica's own libraries. `./gradlew test` and `pluginJars` do not start these tests.

The `auth` and `lobby` servers are not part of what a test checks, so they start once and serve one test after another; only the proxies, with the plugin, their files and their database, are new in every test. A test that fails stops the servers it used, keeps their folders next to its own, and the next test starts new ones.

Several tests run at once, each on its own network: one for every four processors of the machine, four at most. Set another number with `-Pidentica.journeys.parallelism=1`. The server and proxy processes run with a lowered priority and each assumes four processors, so the machine stays usable during a run.

Run one class or one test with `--tests`:

```shell
./gradlew :identica-testing:anvilTest --tests '*CredentialFirstJoinTest'
```

Journeys that start a proxy on what an earlier version of Identica left, such as the database of Identica 2.2.1, are tagged `@Tag("upgrade")` and form the `upgrade` suite, declared in `anvil { suites { ... } }` of the module's build. `anvilTest` leaves them out; run them by hand, and the release workflow runs them once before it publishes:

```shell
./gradlew :identica-testing:anvilUpgradeTest
```

`./gradlew :identica-testing:anvil` runs `anvilTest` and every suite. `anvilScenarios` lists the scenarios, `anvilRun --scenario=<name>` starts one to look around in, and `anvilLogin --account=<id>` and `anvilLogout --account=<id>` manage the accounts Anvil signs in with.

When a test fails, its network is kept under `identica-testing/build/anvil/<scenario>/<run>/`. Each process folder holds an `anvil-console.log`, and Identica's debug logging is enabled in every test network.

## Premium accounts

No test needs a real Minecraft account. Every network starts its own local stand-in for Mojang: the Premium provider asks it whether a username belongs to a premium account, and the proxy asks it to verify a premium login instead of Mojang's session server.

A test takes the stand-in as a parameter and registers the premium accounts that exist:

```java
@Test
@Identica(mode = JourneyMode.SEAMLESS)
void joins(ScenarioContext anvil, YggdrasilMock yggdrasil) {
	SessionIdentity account = yggdrasil.register("Steve");
	Journey.premium(anvil, account).join().on(LOBBY);
}
```

`yggdrasil.register("Alice")` alone makes `Alice` a premium username that an offline player can still try to join with, and `yggdrasil.available(false)` simulates an outage of Mojang's services. The stand-in belongs to the test's network: it starts without accounts and stops with the network.

## Change the configuration

`@Identica` covers the usual differences between networks. For anything else, a test names classes that change the proxy's configuration files through Identica's own models. A file the test leaves out is generated by the plugin, as on a new installation:

```java
@Test
@Identica(configure = NoDisconnectMessages.class)
void endingASessionDisconnectsThePlayer(ScenarioContext anvil) {
}

private static final class NoDisconnectMessages implements Consumer<ProxyConfiguration> {
	@Override
	public void accept(ProxyConfiguration proxy) {
		proxy.messages().getCommands().getAdmin().getSessions().getEnd().setDisconnect(List.of());
	}
}
```

`proxy.engine()`, `proxy.routing()`, `proxy.settings()`, `proxy.providers()`, `proxy.messages()`, `proxy.credential()` (the Credential provider's settings), `proxy.sentinel()`, `proxy.recognition()`, `proxy.verification()` and `proxy.joinRestriction()` (those features' shared settings) return the models a test changes. `proxy.put(path, model)` adds another file, `proxy.omit(path)` leaves a file out, `proxy.corrupt(path, content)` writes one Identica cannot read, `proxy.seed(path, file)` places a file, such as a database an earlier version left, before the proxy first starts, and `ProxyConfiguration.generated(anvil, path, type)` reads a file as the running proxy left it. While the network runs, `ProxyConfiguration.editGenerated(anvil, path, type, change)` changes a file through its model and `ProxyConfiguration.corruptGenerated(anvil, path, content)` replaces it with content Identica cannot read; `Administrator.at(anvil, PROXY).reloads()` and `.failsToReload()` then reload the configuration and expect the configured answer.

A journey about a lockout or a validity window configures a short duration and lets it pass with `.waits(duration)`; it never waits to give the proxy time to act, because every other step already waits for that:

```java
alice.waits(LOCKOUT)
		.rejoin()
		.on(AUTH)
		.login("Secret-123")
		.on(LOBBY);
```

## Several proxies

`@IdenticaCluster` starts two proxies, `proxy-a` and `proxy-b`, that share the `auth` and `lobby` servers and one PostgreSQL database, and that replicate through one Redis unless the test turns replication off. The database and Redis run in containers, so these tests need Docker and are skipped without it.

A journey names the proxy it joins through. Several clients may use one username, each through its own proxy, and `Administrator` runs console commands on a chosen proxy:

```java
@Test
@IdenticaCluster
void disconnectsAPlayerWhoseAccountIsDeletedOnTheOtherProxy(ScenarioContext anvil) {
	Journey alice = Accounts.credential(anvil, "Alice", "Secret-123", PROXY_B).rejoin()
			.on(AUTH)
			.login("Secret-123")
			.on(LOBBY);

	Administrator.at(anvil, PROXY_A).deletes("Alice");

	alice.kickedWith(m -> m.identica().getCommands().getAdmin().getDelete().getDisconnect());
}
```

`@IdenticaCluster(replication = false)` leaves Redis out, for behaviour that must hold when the proxies only share the database. `@IdenticaCluster` takes the same `step` and `complete` routing targets as `@Identica`.
`@IdenticaCluster(configure = ...)` applies the same configuration changes as `@Identica(configure = ...)` to both proxies; a change meant for one of them checks `proxy.name()`. Two clients with one username cannot be on the same backend, because the backend disconnects the earlier one, so a journey that needs both online keeps them on different servers.

## Write a test

A test declares its network with `@Identica` and describes a player with `Journey`:

```java
@Test
@Identica(mode = JourneyMode.INTERACTIVE, providers = Provider.CREDENTIAL)
void registersWithCredential(ScenarioContext anvil) {
	Journey.offline(anvil, "Alice").join()
			.on(AUTH)
			.sees(m -> m.identica().getEngine().getJourney().getStep().getEnrollment().getBody())
			.enroll(Provider.CREDENTIAL)
			.sees(m -> m.credential().getScenario().getRegistration().getPrompt())
			.register("Secret-123")
			.on(LOBBY)
			.sees(m -> m.credential().getCompletion().getRegistration().getBody());
}
```

`@Identica` sets the journey mode and policy, the enabled providers, provider entrypoints, `autoSelectSingleProvider`, and the routing targets. The network is one Velocity proxy, an `auth` server for authentication and registration steps, and a `lobby` that completed players reach. Players join `lobby`; `step` and `complete` name the servers they are routed to while a step waits and once they are done, `auth` and `lobby` unless the test changes them, and a blank target leaves them where they are:

```java
@Test
@Identica(providers = Provider.CREDENTIAL, step = "", complete = "")
void registersOnTheLobbyWithoutAnyRouting(ScenarioContext anvil) {
	Journey.offline(anvil, "Alice").join()
			.on(LOBBY)
			.sees(m -> m.credential().getScenario().getRegistration().getPrompt())
			.register("Secret-123")
			.sees(m -> m.credential().getCompletion().getRegistration().getBody())
			.remainsOn(LOBBY);
}
```

`database` picks where the proxy stores its accounts: `Database.SQLITE`, the default, or `Database.MARIADB`, a MariaDB server in a container that stops with the network, reached through Identica's MySQL backend. A test on MariaDB needs Docker and is skipped without it.

Every test proxy forces the hostname `IdenticaNetwork.LOBBY_HOST` to `lobby`; every journey that names no hostname joins through one without a forced host.

`Journey.of(anvil, client)` creates a player from a `Client` description: `Client.offline(username)` or `Client.premium(account)`, then `.through(host)` for the hostname the client announces, such as `LOBBY_HOST` or a provider's entrypoint, `.from(address)` for the loopback address it connects from, such as `127.0.0.2`, and `.at(proxy)` for a proxy of a cluster. Without `.from(...)` every player connects from `127.0.0.1`, so two clients that should look like different machines name different addresses. Clients of one username need different addresses or proxies:

```java
Journey home = Journey.of(anvil, Client.offline("Alice"));
Journey elsewhere = Journey.of(anvil, Client.offline("Alice").from("127.0.0.2"));
Journey routed = Journey.of(anvil, Client.offline("Bob").through(Provider.CREDENTIAL.getEntrypoint()));
```

Each `Journey` step checks both sides: what the player's client receives, and what the proxy reports on its own console for connections, server changes, and disconnect reasons. A message expectation only considers messages received since the previous one, so a prompt repeated after a reconnect is not satisfied by its earlier occurrence.

Use `Accounts` for players who already have an account.

The `auth` and `lobby` servers remember earlier tests: a player's position and inventory there belong to no test. Keep expectations on what the proxy and the player's client report, and do not rely on the state of a backend world.

A message expectation names the message through Identica's own configuration models: `m.identica()` is `Messages`, `m.credential()` is `CredentialMessages`, `m.premium()` is `PremiumMessages`, `m.sentinel()` is `SentinelMessages`, `m.verification()` is `VerificationMessages`, `m.joinRestriction()` is `JoinRestrictionMessages` and `m.example()` is the example provider's `ExampleMessages`. The models are read from the files the running proxy generated, so the expectation follows the configured text, and a renamed or removed message stops the tests from compiling. Formatting tags are ignored and placeholders match any text. Chain `.with(...)` and `.without(...)` after `.sees(...)` to check what else the same message contains. Do not copy message text into a test.

A player reads what a message hands out, such as a secret or a list of codes, with `.reads(placeholder)` after the `.sees(...)` that matched it. `Authenticator` stands in for an authenticator app, computing the codes for a secret the player read:

```java
Authenticator app = Authenticator.of(alice.command("2fa enroll totp")
		.sees(m -> m.verification().getMethods().getTotp().getPending())
		.reads("secret"));
alice.command("2fa enroll confirm " + app.code());
```

## The examples

Every test proxy installs the example provider from `examples/provider` next to the official ones, disabled unless the test enables it with `providers = Provider.EXAMPLE`. `@Identica(addon = true)` also installs the example addon from `examples/addon`, a separate Velocity plugin that holds back chat and commands until a player has authenticated. The tests under `example` keep both working against the current API.

Text that belongs to no configuration file, such as an addon's own message or a chat line, is matched as plain text. `.chat(message)` sends a chat message, `.seesText(text)` waits for a message containing the text, and `.doesNotSeeText(text)` expects none to arrive. `Administrator.seesOnConsole(texts...)` expects a console line containing every text since the administrator's previous command, such as what an addon logs when it reacts to a reload:

```java
@Test
@Identica(providers = Provider.EXAMPLE, addon = true)
void holdsBackChat(ScenarioContext anvil) {
	Journey.offline(anvil, "Alice").join()
			.on(AUTH)
			.sees(m -> m.example().getPrompt())
			.chat("hello")
			.doesNotSeeText("hello")
			.seesText("Log in before you chat.");
}
```
