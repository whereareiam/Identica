---
title: routing.yml
description: Every setting of routing.yml.
---

`routing.yml` names the servers players are sent to while a login waits for them (`step`) and once they are logged in (`complete`). [Routing players](../../admins/guides/network/routing/index.mdx) explains them with examples.

Every target has the same fields: `target`, `forcedHosts` and `attempts`.

## defaults

The targets for every scenario that does not set its own.

<Setting
  name="step"
  takes="a target"
  default='`"auth"`'
  affects="where a player is sent while their login waits for them, such as for a password"
>

A blank target, with no scenario target either, leaves the player where they are.

</Setting>

<Setting
  name="complete"
  takes="a target"
  default='`"survival"`'
  affects="where a player goes once their login is done"
>

A blank target, with no scenario target either, leaves the player where they are. A player who finished while joining receives the completion messages on the first server they reach.

</Setting>

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
defaults:
  step:
    target: "auth"
  complete:
    target: "survival"
    forcedHosts: false
scenarios: {}
```
  </Tab>
  <Tab value="JSON">
```json
{
  "defaults": {
    "step": {
      "target": "auth"
    },
    "complete": {
      "target": "survival",
      "forcedHosts": false
    }
  },
  "scenarios": {}
}
```
  </Tab>
</Tabs>

## Target fields

<Setting
  name="target"
  takes={"a server name from the proxy's configuration, or `\"\"`"}
  affects="the server the player is sent to"
>

A server the proxy does not know disconnects the player with [`routing.missingServer`](../messages/index.mdx#routing).

</Setting>

<Setting
  name="forcedHosts"
  takes="`true` or `false`"
  default="`false` on `defaults.complete`; elsewhere the value of the less specific target"
  affects="whether the player is sent to the server the proxy forces for the hostname they joined through"
>

`target` is used for hostnames without a forced host. When Velocity lists several servers for a hostname, the first one is used. See [The player's hostname](../../admins/guides/network/routing/index.mdx#the-players-hostname).

</Setting>

### attempts

How often Identica tries to move the player when the server refuses them. See [When a server turns the player away](../../admins/guides/network/routing/index.mdx#when-a-server-turns-the-player-away).

<Setting
  name="mode"
  depth={4}
  takes='`"NONE"`, `"RETRY_ONCE"`, `"RETRY_LIMITED"`, or `"UNTIL_REACHED"`'
  affects="how many attempts are made"
  flag="advanced"
>

| Mode | Attempts |
| --- | --- |
| `NONE` | one |
| `RETRY_ONCE` | two |
| `RETRY_LIMITED` | `maxAttempts` |
| `UNTIL_REACHED` | until the server accepts the player |

</Setting>

<Setting
  name="maxAttempts"
  depth={4}
  takes="an integer"
  affects="the number of attempts of `RETRY_LIMITED`"
  flag="advanced"
>

Other modes ignore it.

</Setting>

<Setting
  name="retryDelay"
  depth={4}
  takes="a duration"
  default='`"0s"`'
  affects="the wait before the next attempt"
  flag="advanced"
>

</Setting>

<Setting
  name="consumeOnReached"
  depth={4}
  takes="`true` or `false`"
  affects="whether Identica forgets the route as soon as the player reaches the server"
  flag="advanced"
>

With `false`, Identica keeps the route until a later route replaces it.

</Setting>

<Setting
  name="consumeOnExhausted"
  depth={4}
  takes="`true` or `false`"
  affects="whether Identica forgets the route once its attempts are used up"
  flag="advanced"
>

With `false`, Identica keeps the failed route until a later route replaces it.

</Setting>

<Setting
  name="scenarios"
  depth={2}
  takes="a map keyed by `authentication`, `registration` or `migration`, in any case"
  default="`{}`"
  affects="the `step` and `complete` targets of one scenario"
>

Add a scenario only when it should differ from `defaults`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
scenarios:
  registration:
    step:
      target: "register"
    complete:
      target: "tutorial"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "scenarios": {
    "registration": {
      "step": {
        "target": "register"
      },
      "complete": {
        "target": "tutorial"
      }
    }
  }
}
```
  </Tab>
</Tabs>

</Setting>

<Setting
  name="overrides.stages"
  takes="a map keyed by stage id, such as `provider`"
  affects="the `step` target while the player waits in that stage of the scenario"
  flag="advanced"
>

</Setting>

<Setting
  name="overrides.steps"
  takes="a map keyed by step name, such as `enrollment`"
  affects="the `step` target while the player waits at that step"
  flag="advanced"
>

A step override wins over a stage override.

</Setting>

```yaml
scenarios:
  registration:
    overrides:
      stages:
        provider:
          target: "register-fallback"
      steps:
        enrollment:
          target: "choose-provider"
```
