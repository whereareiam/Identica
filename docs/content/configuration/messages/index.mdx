`messages.yml` holds what Identica says to players and staff. Every message is written in the file with its default text; this page covers how they are written and the settings that shape many messages at once.

Features and providers keep their messages in their own `messages.yml`, such as `features/verification/messages.yml` or `providers/Credential/messages.yml`. Username messages are in [`identity/username/messages.yml`](../identity/username/index.mdx#messagesyml).

## Formatting

Messages are written in [MiniMessage](https://docs.papermc.io/adventure/minimessage/format/), which covers colors, decorations, and click and hover actions:

```yaml
prefix: "<green>Identica</green> <dark_gray>| "
```

Placeholders are written in curly braces, such as `{prefix}`, `{username}` or `{provider}`. Which placeholders a message has depends on the message; the default text uses them.

## Emptying a message

A message set to an empty string, or a multi-line message set to an empty list, is not shown. That silences the text and changes nothing else: a player who is denied, locked out or disconnected is still denied, locked out or disconnected, with no reason shown.

Recovery codes are the exception, because they are shown once and cannot be read again: they are sent on their own when their message body is empty or does not contain `{entries}`.

## engine

Messages of the login itself. See [Sessions](../../admins/guides/logins/sessions/index.mdx) and [Two connections with one username](../../admins/guides/logins/index.mdx#two-connections-with-one-username) for when they are shown.

<Setting
  name="concurrentLoginKick"
  takes="a list of lines"
  affects="the reason shown to the earlier connection when `REPLACE_EXISTING` disconnects it, and to a connection that was still logging in when another connection logged in to the account"
>

</Setting>

<Setting
  name="concurrentLoginRefused"
  takes="a list of lines"
  default="a notice ending in `This account is already logged in.` and `Log out from the other location first.`"
  affects="the reason shown to the new login when `REJECT_NEW` refuses it because the account is already online"
>

Emptying either message changes only the text. The earlier connection is still disconnected, and the new login is still refused, then with the scenario's general failure message.

</Setting>

<Setting
  name="usernameHeld"
  takes="a list of lines"
  default="a notice reading `This name is being logged in from another location.` and `Try again shortly.`"
  affects="the reason shown to a connection that is refused, or disconnected once its login waits, because another connection, from another address, is logging in under the same username on another proxy of the network"
>

Emptying the message changes only the text; the connection is still refused.

</Setting>

<Setting
  name="concurrentChangeKick"
  takes="a list of lines"
  default="a notice reading `Reconnect to try again.`"
  affects="the reason shown to a connection that is disconnected because its login changed elsewhere while Identica was writing it, typically because the same player continued on another proxy of the network at the same moment"
>

See [A player on two proxies at once](../../admins/guides/network/several-proxies/index.mdx#a-player-on-two-proxies-at-once). Emptying the message changes only the text; the connection is still disconnected.

</Setting>

## routing

Identica disconnects a player when the server it routes them to does not exist on the proxy. The reason comes from the scenario the player is in, and from the shared message when that scenario has none.

<Setting
  name="routing.missingServer"
  takes="a list of lines"
  default="a notice reading `No target server available for routing` and `Please contact a server administrator.`"
  affects="the reason shown when a routing target server is missing and the player's scenario has no message of its own, or the route belongs to no scenario"
>

</Setting>

<Setting
  name="scenarios.authentication.routing.missingServer, scenarios.registration.routing.missingServer, scenarios.migration.routing.missingServer"
  takes="a list of lines"
  default="`[]`"
  affects="the reason shown to a player in that scenario when a routing target server is missing"
>

An empty scenario message shows `routing.missingServer` instead. To disconnect without a reason, empty both.

</Setting>

<Setting
  name="prefix"
  depth={2}
  takes="a string"
  default='`"<green>Identica</green> <dark_gray>| "`'
  affects="the text of `{prefix}`, which most messages start with"
>

Change it to rebrand Identica's messages without editing each of them.

</Setting>

## format

### temporal

How dates and times in messages are written, as [Java date patterns](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/time/format/DateTimeFormatter.html#patterns).

<Setting
  name="date"
  depth={4}
  takes="a date-time pattern string"
  default='`"dd.MM.yyyy"`'
  affects="dates without a time"
>

A blank pattern uses each message's own default.

</Setting>

<Setting
  name="dateTime"
  depth={4}
  takes="a date-time pattern string"
  default='`"dd.MM.yyyy HH:mm:ss"`'
  affects="dates with a time"
>

A blank pattern uses each message's own default.

</Setting>

## commands.pagination

How lists that span several pages, such as `/identica help`, show their page navigation.

<Setting
  name="showPaginationIfOnePage"
  takes="`true` or `false`"
  default="`false`"
  affects="whether pagination controls are shown when there is only one page"
>

</Setting>

<Setting
  name="format"
  takes="a string"
  default='`"\n {previous}<white>Pagination</white> <gray>[{current}/{max}]</gray>{next} \n"`'
  affects="the navigation line"
>

Placeholders: `{previous}` and `{next}` for the controls below, `{current}` for the page and `{max}` for the number of pages.

</Setting>

<Setting
  name="showPreviousEvenIfFirst"
  takes="`true` or `false`"
  default="`false`"
  affects="whether the previous-page control is still shown on the first page"
>

</Setting>

<Setting
  name="previousTagFormat"
  takes="a string"
  default='`"<red><click:run_command:/identica help {previousPage}>«</red> "`'
  affects="the control to the previous page"
>

`{previousPage}` is the number of that page.

</Setting>

<Setting
  name="showNextEvenIfLast"
  takes="`true` or `false`"
  default="`false`"
  affects="whether the next-page control is still shown on the last page"
>

</Setting>

<Setting
  name="nextTagFormat"
  takes="a string"
  default='`" <green><click:run_command:/identica help {nextPage}>»</green>"`'
  affects="the control to the next page"
>

`{nextPage}` is the number of that page.

</Setting>
