`commands.yml` содержит собственные команды Identica — их псевдонимы, права, описания и синтаксис — и несколько настроек, общих для всех команд. Функции и провайдеры хранят свои команды в собственных `commands.yml` с той же структурой, например `providers/Credential/commands.yml` или `features/verification/commands.yml`. Команды для персонала перечислены в руководстве [Управление аккаунтами](../../admins/guides/accounts/managing-accounts/index.mdx).

## commands

Все команды; ключом служит идентификатор команды, например `admin-reload`.

<Callout title="Ключи команд" type="warn">
  Меняйте значения внутри команды, но сохраняйте её ключ: Identica находит каждую свою команду по ключу, и команда с переименованным ключом остаётся без своих настроек.
</Callout>

У всех команд одинаковые поля.

Псевдоним — это слово, например `help`, или фраза, например `admin session list`; подкоманды `/identica` используют фразы. Включённая команда без единого псевдонима не регистрируется, и при запуске в консоли появляется предупреждение.

</Setting>

  affects="право, которое нужно игроку для использования команды"
>

Пустая строка разрешает команду всем.

</Setting>

<Setting
  name="description"
  depth={4}
  takes="строку"
  affects="описание команды в `/identica help`"
>

</Setting>

<Setting
  name="usage"
  depth={4}
  takes="строку"
  affects="синтаксис, который показывается в справке и в сообщениях об ошибках, и на то, какие аргументы принимает команда"
  flag="advanced"
>

`usage` — это одновременно то, что читают игроки, и то, что принимает команда: по нему Identica определяет, какие аргументы обязательные, а какие — необязательные.

Синтаксис:

- `<name>` — обязательный аргумент
- `[name]` — необязательный аргумент
- `<name...>` или `[name...]` — аргумент, который забирает остаток строки
- плейсхолдеры `{...}` только отображаются и никогда не разбираются

Во встроенных строках `usage` часто встречаются такие плейсхолдеры:

- `{alias}` — псевдоним, который используется сейчас
- `{command}` — путь корневой команды

Правила:

- Сохраняйте имена аргументов из `usage` по умолчанию. Имя, которого у команды нет, не даёт команде зарегистрироваться, и консоль сообщает об этом.
- Псевдонимы берутся только из `aliases`, никогда из `usage`.
- Необязательный аргумент можно убрать из `usage`; тогда команда перестаёт его принимать, а справка и сообщение о неверном синтаксисе перестают его показывать.
- Настройки никогда не меняют `usage`: если настройка делает необязательный аргумент ненужным, например `changePassword.requireRepeat` провайдера Credential, аргумент остаётся в синтаксисе, пока вы его не уберёте.

Примеры:

- `"{command} {alias} <target> [provider]"` означает:
  - показываются корневая команда и псевдоним, который использовал игрок
  - `target` — обязательный аргумент
  - `provider` — необязательный аргумент

- `"{alias}"` означает:
  - команда не принимает аргументов
  - показывается только псевдоним

</Setting>

<Setting
  name="cooldown"
  depth={4}
  takes="`enabled`, `duration` и `group`"
  affects="как скоро игрок может снова выполнить команду"
>

Команда на кулдауне отказывает игроку, который выполнял её меньше `duration` секунд назад, и отправляет ему `commands.exceptions.cooldown` из `messages.yml`, где `{content}` — оставшиеся секунды; при пустом сообщении команда отказывает молча. Кулдаун начинается, как только команда принята, независимо от того, удалась ли она, так что неверно набранный пароль тоже считается; неверный синтаксис или отсутствие права кулдаун не запускают.

Кулдауны хранятся для каждого игрока в памяти прокси, заканчиваются, когда игрок уходит или прокси перезапускается, и каждый прокси сети ведёт свои. Консоль никогда не ждёт. У стандартных команд Identica собственный кулдаун в две секунды; у команд без раздела `cooldown` кулдауна нет.

</Setting>

<Setting
  name="enabled"
  depth={5}
  takes="`true` или `false`"
  default="`false`"
  affects="есть ли у команды кулдаун"
>

</Setting>

<Setting
  name="duration"
  depth={5}
  takes="целое число секунд"
  default="`0`"
  affects="сколько команда остаётся на кулдауне после того, как игрок её выполнил"
>

Длительность `0` или меньше означает отсутствие кулдауна, даже если `enabled` равно `true`.

</Setting>

<Setting
  name="group"
  depth={5}
  takes="строку"
  default='`""`'
  affects="какие команды делят кулдаун"
>

Пустая группа даёт команде собственный кулдаун, общий для её псевдонимов. Команды с одной и той же группой делят один кулдаун, даже из разных файлов `commands.yml`: выполнение любой из них ставит на кулдаун все команды группы для этого игрока — на длительность выполненной команды.

</Setting>

<Setting
  name="arguments"
  depth={4}
  takes="словарь «имя аргумента — описание»"
  affects="то, как каждый аргумент описан в справке"
>

Он только описывает аргументы; какие аргументы существуют, определяет `usage`.

</Setting>

<Setting
  name="hide"
  depth={4}
  takes="`true` или `false`"
  default="`false`"
  affects="то, скрывает ли `/identica help` эту команду"
>

Скрытая команда продолжает работать.

</Setting>

## Встроенные группы команд [#built-in-command-groups]

`commands.yml` по умолчанию содержит такие команды:

- Основные: `main`, `help`, `enroll`, `availability-username`
- Администрирование: `admin`, `admin-reload`, `admin-clear`, `admin-clear-confirm`, `admin-clear-cancel`, `admin-delete`, `admin-delete-confirm`, `admin-delete-cancel`, `admin-reservation-set`, `admin-reservation-info`, `admin-reservation-delete`, `admin-session`, `admin-session-list`, `admin-session-info`, `admin-session-end`, `admin-username-duplicates`, `admin-verification-reset`
- Миграция: `migration-list`, `migration-start`, `migration-cancel`, `migration-primary`, `migration-drop`
- Верификация: `verification`, `verification-status`, `verification-enroll`, `verification-confirm`, `verification-enroll-confirm`, `verification-use`, `verification-disable`, `verification-enroll-cancel`
