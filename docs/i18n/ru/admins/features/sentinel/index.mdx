Sentinel следит за повторяющимися попытками и на время блокирует подключение, которое за ними стоит. Каждый sentinel считает свой вид попыток:

| Sentinel | Что считает | По умолчанию |
| --- | --- | --- |
| спорное подключение | подключения с одного адреса, отклонённые потому, что под их ником уже входит другой адрес | включён: 5 отказов блокируют адрес на 1 минуту |
| спам продолжениями | попытки продолжить ожидающий вход или перейти в нём дальше | выключен |
| перебор паролей Credential | неверные пароли | включён: 5 неверных паролей блокируют игрока на 5 минут |

Sentinel спорных подключений считает по адресу, какой бы ник ни использовало каждое подключение, поэтому он останавливает того, кто перебирает ники, под которыми сейчас идёт вход. См. [Два подключения с одним ником](../../guides/logins/index.mdx#two-connections-with-one-username).

Защита от перебора паролей принадлежит провайдеру Credential и настраивается в его настройках; см. [Защита от перебора паролей](../../providers/official/credential/brute-force/index.mdx).

## Включение и выключение [#turning-sentinels-on-and-off]

У каждого sentinel есть свой переключатель `enabled` в `features/sentinel/settings`:

```yaml
sentinels:
  resumeSpam:
    enabled: true
    maxAttempts: 10
    lockout:
      enabled: true
      duration: "30s"
  contestedConnection:
    enabled: true
    maxAttempts: 5
```

Проверки, которые выполняются до того, как Identica узнаёт провайдера игрока, например sentinel спорных подключений, подчиняются только этим настройкам. Проверки, которые выполняются, когда провайдер уже известен, например защита от перебора паролей Credential, учитывают и переключатель провайдера:

```yaml
providers:
  - id: "credential"
    features:
      sentinel:
        enabled: false
```

## Предупреждения и сообщения [#warnings-and-messages]

Sentinel может предупредить перед блокировкой: при `warning.enabled` и `warning.thresholdPercentage: 70` игрок с `maxAttempts: 10` получает предупреждения начиная с восьмой попытки.

Сообщения о блокировке находятся в `features/sentinel/messages`; `{seconds}` — оставшееся время. Пустое сообщение отключает текст, но блокировка всё равно действует.

С [репликацией](../../guides/network/several-proxies/index.mdx) счётчики и блокировки общие для всех прокси сети.

Все настройки описаны на странице [Настройки Sentinel](../../../configuration/features/sentinel/index.mdx).
