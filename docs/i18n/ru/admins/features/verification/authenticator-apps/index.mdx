Встроенный метод верификации `totp` работает с любым приложением-аутентификатором, которое понимает стандартные коды, например с Google Authenticator, Aegis или менеджером паролей.

## Настройка [#setting-it-up]

1. Игрок вводит `/2fa enroll totp`. Identica показывает секрет и ссылку, которую может импортировать приложение.
2. Игрок добавляет аккаунт в приложение и вводит `/2fa enroll confirm <code>` с кодом, который показывает приложение.
3. Identica один раз показывает игроку его коды восстановления. Их нужно сохранить в надёжном месте.

Настройка, не подтверждённая в течение `enrollmentTtl`, по умолчанию 10 минут, отменяется. Когда игрок подтверждает настройку, новый метод выбирается для провайдера, через который он вошёл, если только `autoSelectCurrentProvider` не равен `false`.

## Что показывает приложение [#what-the-app-shows]

Название записи в приложении задают `issuer` и `labelFormat` в `features/verification/settings`:

```yaml
totp:
  displayName: "Authenticator App"
  issuer: "My Network"
  labelFormat: "{player}@{providerId}"
```

`{player}` — ник игрока, а `{providerId}` — провайдер, через который он настроил метод. `displayName` — название метода в сообщениях самой Identica.

## Коды и часы [#codes-and-clocks]

Коды состоят из `digits` цифр и меняются каждые `period` — по умолчанию 6 цифр и 30 секунд, как ожидает большинство приложений. Меняйте эти значения, только если их поддерживают все приложения ваших игроков; изменение не применяется к уже настроенным приложениям.

Телефон, часы которого немного спешат или отстают, показывает код соседнего окна. `allowedPastWindows` и `allowedFutureWindows`, по умолчанию по одному, позволяют принимать и такие коды. Чем больше окон, тем больше прощается расхождение часов, но тем дольше принимаются и коды. При любых окнах каждый код принимается один раз: игрок, у которого приложение спешит и который ввёл код будущего окна, ждёт следующего кода до окна после него.

## Коды восстановления [#recovery-codes]

Игрок, потерявший приложение, входит вместо этого с кодом восстановления. По умолчанию он получает 8 кодов из 10 символов, показанных группами по 4. Каждый код работает один раз.

Игроку без приложения и без кодов восстановления нужно, чтобы персонал сбросил его верификацию командой `/identica admin 2fa reset <player>`.

Коды восстановления показываются один раз и больше не могут быть прочитаны, поэтому Identica отправляет их, даже если их сообщение пустое.

Все настройки описаны на странице [Настройки верификации](../../../../configuration/features/verification/index.mdx#totp).
