У каждого сценария в `engine.yml` есть режим прохождения и политика прохождения. Вместе они определяют, спрашивает ли Identica у игрока что-либо, например какой провайдер использовать, или продолжает сама везде, где может.

| Сценарий | Режим по умолчанию | Политика по умолчанию |
| --- | --- | --- |
| аутентификация | `SEAMLESS` | `PREFER` |
| регистрация | `SEAMLESS` | `PREFER` |
| миграция | `INTERACTIVE` | `PREFER` |

## Режимы [#modes]

<Tabs items={["INTERACTIVE", "SEAMLESS"]}>
  <Tab value="INTERACTIVE">
    Identica может показать игроку запрос и дождаться ответа: выбрать провайдера, ввести пароль, подтвердить код из приложения-аутентификатора.

    Для большинства сетей это более простой выбор: игрок видит, чего от него ждут. Новый игрок, который заходит с офлайн-клиента под ником лицензионного аккаунта, выбирает провайдера сам, а не получает сразу требование лицензионного входа: если сценарий регистрации работает в режиме `INTERACTIVE`, проверка Premium при рукопожатии для ника без аккаунта пропускается.
  </Tab>
  <Tab value="SEAMLESS">
    Identica продолжает сама, насколько позволяет провайдер, и спрашивает игрока, только когда провайдеру нужен ввод.

    Режим подходит сетям, провайдеры которых могут распознавать игроков автоматически. Подвох в первом входе пиратского (офлайн) игрока под ником лицензионного аккаунта: провайдер Premium с более высоким приоритетом требует лицензионный вход прямо при рукопожатии, ещё до того, как игрок увидит какой-либо выбор. Клиент не может его пройти и отключается с ошибкой «недействительная сессия», и может показаться, что на сервер пускают только с лицензией. Следующий вход с того же адреса в пределах [`attemptTtl`](../../../../configuration/providers/index.mdx#attemptttl) продолжается со следующим провайдером.

    [Способ определения `CLIENT_PROFILE`](../../../providers/official/premium/detection/index.mdx) провайдера Premium позволяет избежать этого для клиентов версии 1.19.1 и новее.
  </Tab>
</Tabs>

## Политики [#policies]

- `PREFER` сначала использует настроенный режим и переходит на другой, если настроенный не может завершить вход. Это правильный выбор для большинства сетей.
- `STRICT` использует только настроенный режим.

При `SEAMLESS` и `STRICT` Identica никогда не показывает запросы. Если входу нужен ввод игрока, например выбор провайдера или пароль, игрок вместо запроса отключается с сообщением `engine.journey.step.interactionRequired`. Провайдер, которому ввод нужен всегда, — например Credential без [распознавания](../../../features/recognition/index.mdx), — тогда никого не сможет зарегистрировать или впустить.

## Пропуск выбора провайдера [#skipping-the-provider-choice]

Если новый игрок может зарегистрироваться только у одного провайдера, в выборе провайдера при регистрации в режиме `INTERACTIVE` всего один вариант. `autoSelectSingleProvider: true` в сценарии регистрации выбирает его, не спрашивая игрока:

```yaml
scenarios:
  registration:
    journeyMode: "INTERACTIVE"
    autoSelectSingleProvider: true
```

Игрок, который заходит через [имя хоста](../provider-selection/index.mdx#hostnames) провайдера, тоже пропускает выбор.

Все настройки сценариев описаны в [`engine.yml`](../../../../configuration/engine/index.mdx).
