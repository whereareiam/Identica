Начните с консоли прокси: Identica пишет там, что пошло не так. Для подробностей задайте `level: 3` в `settings.yml`, чтобы включить отладочные логи, и выполните `/identica admin reload`.

## Запуск [#startup]

<Accordions type="multiple">
  <Accordion title="Первый запуск будто завис">
    При первом запуске, а также при первом запуске с другим типом базы данных Identica скачивает свои библиотеки. Это может занять время, и всё это время в консоли может не появляться ничего нового. Прокси нужен доступ в интернет, и он должен иметь возможность обращаться к сайтам, защищённым Cloudflare.
  </Accordion>
  <Accordion title="Всех игроков отклоняет, будто серверы аутентификации недоступны">
    Запуск Identica завершился ошибкой. Пока Identica не запустится, она отклоняет каждое подключение стандартным игровым сообщением о недоступности серверов аутентификации, поэтому без входа никто не попадёт на бэкенд-сервер. Причина указана в консоли. Частые причины:

    - файл конфигурации, который не удаётся прочитать, или значение, которое Identica не принимает, например неизвестный `type` в `persistence.yml` или неизвестная `concurrencyPolicy`
    - недоступная база данных или сервер MySQL старше 8.0.19; см. [База данных](../guides/network/database/index.mdx)
    - недоступный Redis при включённой репликации; см. [Несколько прокси](../guides/network/several-proxies/index.mdx)
    - не удалось скачать библиотеку
    - папку данных записал более новый релиз Identica

    Устраните причину и перезапустите прокси.
  </Accordion>
  <Accordion title="Настройка в файле провайдера после обновления вернулась к значению по умолчанию">
    Identica обновляет свои файлы и файлы своих функций, но не файлы провайдеров в `providers/`. Если у настройки провайдера изменились имя или место, она возвращается к значению по умолчанию; такие изменения перечислены в примечаниях к релизу. См. [Обновление Identica](../guides/upgrading/index.mdx).
  </Accordion>
  <Accordion title="Пропали мои комментарии в файлах конфигурации">
    При каждом запуске и каждой перезагрузке Identica дополняет каждый файл недостающими настройками и записывает его заново. Ваши значения сохраняются, комментарии — нет.
  </Accordion>
</Accordions>

## Вход на сервер [#joining]

<Accordions type="multiple">
  <Accordion title="Новых игроков при первом входе отключает с сообщением о недействительной сессии">
    Игрок использует ник лицензионного аккаунта, но заходит с пиратского (офлайн) клиента, а `choice` регистрации — `AUTOMATIC`. Тогда Premium запрашивает лицензионный вход, который клиент не может пройти. При следующем входе игрок продолжает через Credential. Установите `choice` регистрации в `PROMPTED` или добавьте способ определения `CLIENT_PROFILE` провайдера Premium. См. [Выбор провайдера](../guides/logins/provider-choice/index.mdx).
  </Accordion>
  <Accordion title='Игроков отключает с сообщением «No target server available for routing»'>
    Цель маршрутизации указывает на сервер, которого нет в конфигурации прокси. Проверьте `routing.yml`, включая записи сценариев; сгенерированные цели `auth` и `survival` — лишь примеры. См. [Маршрутизация игроков](../guides/network/routing/index.mdx).
  </Accordion>
  <Accordion title="После входа игроки остаются на месте">
    Либо цель `complete` пуста, либо целевой сервер не принял игрока — например, из-за белого списка, — и попытки закончились. Тогда игрок видит причину, которую назвал сервер. См. [Когда сервер не принимает игрока](../guides/network/routing/index.mdx#when-a-server-turns-the-player-away).
  </Accordion>
  <Accordion title="Игрокам сообщают, что с этим ником уже входят из другого места">
    Другое подключение с другого адреса входит с тем же ником. Ник снова освободится, когда тот вход завершится, игрок выйдет или истечёт `pipelineTtl` сценария. После падения прокси ник освобождается через `heartbeatTimeout`. См. [Два подключения с одним ником](../guides/logins/index.mdx#two-connections-with-one-username).
  </Accordion>
  <Accordion title="Игрокам сообщают, что в аккаунт уже вошли">
    `concurrencyPolicy` равна `REJECT_NEW`, а у аккаунта есть сессия через другое подключение. После падения прокси эта сессия длится, пока не истечёт `heartbeatTimeout`. `/identica admin session end <player>` сразу завершает её. См. [Сессии](../guides/logins/sessions/index.mdx).
  </Accordion>
  <Accordion title="Игроков отключает с просьбой переподключиться">
    Один и тот же игрок одновременно попал на два прокси, и другой прокси сохранил данные первым. После переподключения вход продолжится с того, что тот сохранил. См. [Игрок на двух прокси одновременно](../guides/network/several-proxies/index.mdx#a-player-on-two-proxies-at-once).
  </Accordion>
  <Accordion title="Игрока отклоняют, потому что его ник занят">
    Ник принадлежит другому аккаунту, и правила конфликтов отклоняют входящего игрока. См. [Ники и конфликты](../guides/accounts/usernames/index.mdx).
  </Accordion>
  <Accordion title="Распознавание никого не распознаёт">
    Возможно, Identica видит вместо настоящих адресов игроков loopback- или частные адреса, которым распознавание по умолчанию не доверяет. Сделайте так, чтобы прокси получал настоящие адреса клиентов, например через PROXY protocol за балансировщиком нагрузки. См. [Распознавание](../features/recognition/index.mdx).
  </Accordion>
</Accordions>

## Команды и конфигурация [#commands-and-configuration]

<Accordions type="multiple">
  <Accordion title="Перезагрузка сообщает об ошибке">
    В ответе перечислены все файлы, которые не удалось прочитать. Они сохраняют прежние значения, остальные перезагружаются, а сломанный файл не перезаписывается — исправьте его и перезагрузите снова. Изменения в `persistence.yml` требуют перезапуска.
  </Accordion>
  <Accordion title="Команда не существует">
    Возможно, команда выключена или у неё нет псевдонима в соответствующем `commands.yml`. Включённая команда без псевдонима не регистрируется, и при запуске консоль предупреждает об этом. См. [Команды](../../configuration/commands/index.mdx).
  </Accordion>
  <Accordion title="На Velocity не принимаются пароли со спецсимволами">
    При `useBrigadier: true` в `commands.yml` Velocity разбирает ввод команд строже и отклоняет некоторые символы ещё до того, как их увидит Identica. Оставьте `false`.
  </Accordion>
</Accordions>
