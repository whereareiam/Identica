`providers/Credential/settings.yml` holds Credential's settings. [Passwords](../passwords/index.mdx) and [Brute-force protection](../brute-force/index.mdx) explain how they work together.

## scenario

### registration

<Setting
  name="enabled"
  depth={4}
  takes="`true` or `false`"
  default="`true`"
  affects="whether new players can register with Credential, and accounts can move to it"

</Setting>

</Setting>

### authentication.bruteforce

<Badge type="warning">Advanced</Badge>

Counts wrong passwords and locks the player out after too many. It follows the [sentinel](../../../../features/sentinel/index.mdx) switch of Credential's entry in `providers/providers.yml`.

<Setting
  name="maxAttempts"
  depth={4}
  takes="a non-negative integer"
  default="`5`"
  affects="how many wrong passwords are allowed within `lockout.duration`"
>

`0` turns the protection off.

</Setting>

<Setting
  name="lockout.enabled"
  depth={4}
  takes="`true` or `false`"
  default="`true`"
  affects="whether reaching `maxAttempts` locks the player out"
>

When `false`, wrong passwords are still counted and warned about, but nobody is locked out.

</Setting>

<Setting
  name="lockout.duration"
  depth={4}
  takes="a positive duration"
  default='`"5m"`'
  affects="how long a wrong password is counted, and how long a lockout lasts"
  flag="advanced"
>

A zero or negative duration stops counting wrong passwords.

</Setting>

<Setting
  name="warning.enabled"
  depth={4}
  takes="`true` or `false`"
  default="`true`"
  affects="whether a wrong password is answered with the number of attempts left"
>

</Setting>

<Setting
  name="warning.thresholdPercentage"
  depth={4}
  takes="an integer from `0` to `100`"
  default="`50`"
  affects="from which share of `maxAttempts` the warning is shown"
>

With `maxAttempts: 5` and `50`, the warning starts at the third wrong password, which leaves two. Values outside `0` to `100` are treated as the nearest end.

</Setting>

<Setting
  name="changePassword.requireRepeat"
  takes="`true` or `false`"
  default="`true`"
  affects="whether `/changepassword <current> <new> [repeat]` requires the `repeat` argument"
>

With `true`, a missing `repeat` counts as a mismatch. With `false`, `repeat` is optional, but a given one must match. The command's syntax does not change with this setting: remove `[repeat]` from the `change-password` usage in `providers/Credential/commands.yml` to stop offering it, as described for [usage](../../../../../configuration/commands/index.mdx#usage).

</Setting>

## cryptography

How Credential hashes passwords. See [Hashing](../passwords/index.mdx#hashing).

<Setting
  name="algorithm"
  takes='`"bcrypt"` or `"argon2"`, in any case'
  default='`"bcrypt"`'
  affects="how new password hashes are made"
  flag="advanced"
>

Existing hashes keep working with the algorithm that made them. A blank or unknown value makes registrations and password changes fail.

`bcrypt` reads only the first 72 bytes of a password; anything after that is ignored. A character outside ASCII takes two to four bytes, so this can apply below `maxLength`. `argon2` has no such limit.

</Setting>

<Setting
  name="autoupgrade"
  takes="`true` or `false`"
  default="`true`"
  affects="whether a hash made with another algorithm is remade with `algorithm` when its player logs in successfully"
>

</Setting>

<Setting
  name="algorithms.bcrypt.cost"
  takes="a positive integer"
  default="`12`"
  affects="the work factor of new bcrypt hashes"
  flag="advanced"
>

Each step up doubles the time a hash takes, for logins and for guessing alike.

</Setting>

<Setting
  name="algorithms.argon2.iterations"
  takes="a positive integer"
  default="`3`"
  affects="the iterations of new Argon2id hashes"
  flag="advanced"
>

</Setting>

<Setting
  name="algorithms.argon2.parallelism"
  takes="a positive integer"
  default="`1`"
  affects="the parallelism of new Argon2id hashes"
  flag="advanced"
>

</Setting>

<Setting
  name="algorithms.argon2.memoryKb"
  takes="a positive integer"
  default="`65536`"
  affects="the memory, in kilobytes, each new Argon2id hash uses"
  flag="advanced"
>

A value of `0` or lower in a cost setting makes hashing fail, and with it registrations and password changes.

</Setting>
