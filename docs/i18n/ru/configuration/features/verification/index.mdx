Верификация добавляет второй шаг, который можно потребовать после того, как провайдер уже определил игрока.
На практике это значит, что игрок сначала проходит аутентификацию через провайдер, а затем подтверждает вход дополнительным методом верификации — и только после этого процесс может продолжиться.
Методы верификации могут быть встроенными или поставляться установленными аддонами.

## Верификация на практике [#verification-in-practice]

Игрок заходит через провайдер `credential` и правильно вводит пароль.
Вместо того чтобы сразу завершить вход, Identica запрашивает код встроенного метода верификации TOTP, который используется по умолчанию.
Игрок вводит текущий код из приложения-аутентификатора, верификация проходит успешно — и только тогда процесс входа завершается.

Каждый код аутентификатора принимается для аккаунта один раз — подтверждает ли он вход или защищённое действие, например отключение метода; код, которым было подтверждено подключение метода, тоже считается использованным. После того как код принят, коды его временного окна и более ранних окон отклоняются на всех прокси, которые используют общую базу данных, и игрок вводит следующий код. На отклонённый код игрок получает тот же ответ, что и на неверный. Резервные коды тоже одноразовые.

Если верификация не обязательная, а опциональная, тот же провайдер может работать, не навязывая второй шаг каждому игроку и в каждой ситуации.

Верификация встроена в Identica. Общие значения по умолчанию находятся в `features/verification/`; провайдеры переопределяют их в `providers[].features.verification`. Подробнее — в разделе [Настройки](./settings/index.mdx).
