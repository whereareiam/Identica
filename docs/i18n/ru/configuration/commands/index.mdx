## Общее поведение [#behavior]

Раздел `behavior` задаёт поведение, которое касается команд в целом и не привязано к определению какой-то одной команды.

### help

#### sortAlphabetically

- Принимает: `true` или `false`
- По умолчанию: `true`
- Влияет на: сортирует ли команда помощи записи по алфавиту перед выводом

Если указано `false`, справка сохраняет естественный порядок регистрации команд, а не сортирует их по алфавиту принудительно.

### suggestions

#### playerLimit

- Принимает: целое число
- По умолчанию: `25`
- Влияет на: максимальное число подсказок с никами других игроков, которые возвращают поставщики подсказок команд

Если значение `0` или меньше, такие подсказки фактически отключаются.

### clear

#### confirmTtl

- Принимает: длительность
- По умолчанию: `"60s"`
- Влияет на: сколько времени действителен ожидающий подтверждения запрос администратора на очистку

Это промежуток времени между запросом на очистку аккаунта и её подтверждением.

### sessions

#### listPageSize

- Принимает: целое число
- По умолчанию: `7`
- Влияет на: сколько записей выводится на одной странице в списках сессий для администратора

### migration

#### confirmTtl

- Принимает: длительность
- По умолчанию: `"60s"`
- Влияет на: сколько времени действителен ожидающий подтверждения запрос на миграцию

### useBrigadier

<Badge type="warning">Осторожно</Badge>

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: как Identica регистрирует команды на платформах, поддерживающих несколько режимов регистрации

<ContentTabs items={["Velocity"]}>
  <ContentTab value="Velocity">
    В Velocity этот параметр переключает режим регистрации в менеджере команд между прямой (raw) регистрацией и регистрацией через Brigadier.

    Для Identica `RAW` обычно более безопасный вариант по умолчанию.

    В режиме `RAW` ввод команд передаётся с меньшими ограничениями.
    Это особенно полезно, например, для паролей: ввод может содержать более широкий набор символов и меньше зависит от правил разбора Brigadier.

    В режиме `BRIGADIER` ввод обрабатывается строже.
    Обычные символы по-прежнему работают, но корректно через разбор Brigadier проходит лишь ограниченный набор спецсимволов.
    Это может стать проблемой, если ваши правила для учётных данных или ожидаемый ввод команд рассчитаны на более широкую поддержку спецсимволов.

    Ещё одно практическое различие — обработка ошибок.
    В режиме `RAW` Identica может аккуратнее показывать свои собственные сообщения о неверном вводе и подсказки по синтаксису.
    В режиме `BRIGADIER` эти собственные сообщения об исключениях и неверных командах срабатывают менее надёжно, потому что Brigadier может отклонить ввод раньше, на более ранней стадии разбора.
  </ContentTab>
</ContentTabs>

## commands

Карта `commands` содержит сами определения команд; ключами служат внутренние идентификаторы определений.

<Callout title="Ключи команд" type="warn">
  У встроенных команд меняйте значения внутри определения команды, но не переименовывайте без необходимости сами ключи карты.
  Обработчики встроенных команд находят определения именно по этим внутренним идентификаторам.
</Callout>

Все записи в `commands` устроены одинаково.

### Поля определения команды [#command-definition-fields]

#### enabled

- Принимает: `true` или `false`
- Влияет на: регистрируется ли определение команды вообще

Если указано `false`, Identica не регистрирует команду по этому определению.

#### aliases

- Принимает: список строк-псевдонимов
- Влияет на: какие названия команд и фразы подкоманд регистрируются

Псевдонимы могут быть отдельными словами, например `help`, или командными фразами, например `admin session list`.
Включённая команда без единого псевдонима не регистрируется: Identica записывает в лог предупреждение с её названием и запускает остальные команды как обычно.

#### permission

- Принимает: строку
- Влияет на: право, необходимое для использования команды по этому определению

Пустая строка означает, что для этого определения дополнительная проверка прав не настроена.

#### description

- Принимает: строку
- Влияет на: справку и вывод метаданных для этой команды

#### usage

<Badge type="warning">Для опытных</Badge>

- Принимает: строку
- Влияет на: синтаксис использования, который показывается в справке и других сообщениях о командах, а также на расстановку обязательных и необязательных аргументов при регистрации команды

`usage` — это отчасти документация, а отчасти структура.
По этой строке Identica определяет, какие аргументы итоговой зарегистрированной команды обязательные, а какие — необязательные.

Это полезно, если вы хотите, чтобы справка и синтаксис команд лучше соответствовали тому стилю, которым, по-вашему, будут пользоваться игроки или персонал.
Например, можно поддерживать текст использования в соответствии с изменёнными псевдонимами, предпочтительным порядком работы с командой или более наглядным разделением обязательных и необязательных аргументов.

Синтаксис `usage` работает так:

- `<name>` — обязательный аргумент
- `[name]` — необязательный аргумент
- `<name...>` или `[name...]` — «жадный» аргумент в строке использования
- плейсхолдеры `{...}` парсер аргументов игнорирует; они нужны только для отображаемого текста синтаксиса

Во встроенных строках использования часто встречаются такие плейсхолдеры:

- `{alias}` — псевдоним, который используется сейчас
- `{command}` — путь корневой команды

Важные правила:

- Имена аргументов внутри `<...>` и `[...]` должны совпадать с реальными именами аргументов, которые разбирает обработчик команды
- `usage` сам по себе не задаёт псевдонимы — они по-прежнему берутся из поля `aliases`
- Если элемент `usage` ссылается на имя аргумента, которого нет в разобранной команде, регистрация завершается ошибкой
- Поскольку `usage` влияет не только на отображение, но и на структуру, небрежное изменение может рассогласовать определение команды с реальными аргументами обработчика
- Необязательный аргумент, который реализован в обработчике, можно не указывать в `usage`; тогда зарегистрированная команда перестаёт его принимать, а справка и сообщение о неверном синтаксисе перестают его показывать
- Настройки никогда не переписывают `usage`: если какая-то настройка делает необязательный аргумент ненужным, например `changePassword.requireRepeat` провайдера Credential, аргумент остаётся в синтаксисе, пока вы не уберёте его из `usage`

Провайдеры и функции хранят определения своих команд в собственных `commands.yml`, например `providers/Credential/commands.yml` или `features/verification/commands.yml`, с той же структурой определений, что и в этом файле.

Пример:

- `"{command} {alias} <target> [provider]"` означает:
  - путь корневой команды и выбранный псевдоним подставляются в текст синтаксиса
  - `target` — обязательный аргумент
  - `provider` — необязательный аргумент

- `"{alias}"` означает:
  - через `usage` не задано ни одного аргумента команды
  - отображается только плейсхолдер псевдонима

#### cooldown

- Принимает: объект кулдауна
- Влияет на: кулдаун отдельной команды, который применяет адаптер команд

##### enabled

- Принимает: `true` или `false`
- Влияет на: включён ли кулдаун

##### duration

- Принимает: целое число
- Влияет на: длительность кулдауна, которую использует система команд

##### group

- Принимает: строку
- По умолчанию: `"default"`
- Влияет на: к какой группе кулдаунов относится команда

Команды из одной группы могут делить общий кулдаун — это зависит от правил фреймворка команд.

#### arguments

- Принимает: карту «имя аргумента — описание»
- Влияет на: собственные описания аргументов, которые используются в справке и при форматировании синтаксиса

Сама по себе эта карта не задаёт логику разбора.
Она лишь описывает аргументы, которые уже реализованы в обработчике команды.

#### hide

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: скрыта ли команда из справки

Используется для внутренних или вспомогательных для процесса определений команд, которые должны существовать, но не должны показываться в обычной справке.

## Встроенные группы команд [#built-in-command-groups]

Текущие значения по умолчанию создают встроенные определения в следующих группах:

- Основные: `main`, `help`, `enroll`, `availability-username`
- Администрирование: `admin`, `admin-reload`, `admin-clear`, `admin-clear-confirm`, `admin-clear-cancel`, `admin-delete`, `admin-delete-confirm`, `admin-delete-cancel`, `admin-reservation-set`, `admin-reservation-info`, `admin-reservation-delete`, `admin-session`, `admin-session-list`, `admin-session-info`, `admin-session-end`, `admin-username-duplicates`, `admin-verification-reset`
- Миграция: `migration-list`, `migration-start`, `migration-cancel`, `migration-primary`, `migration-drop`
- Верификация: `verification`, `verification-status`, `verification-enroll`, `verification-confirm`, `verification-enroll-confirm`, `verification-use`, `verification-disable`, `verification-enroll-cancel`
