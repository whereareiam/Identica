The providers configuration controls which identity providers are enabled and how provider-specific behavior is applied.
Use this file to enable providers, set priority and entrypoints, tune provider-specific session behavior, and apply feature-owned provider fields.

Shared feature settings and provider-scoped feature overrides are documented under [Features](../features/index.mdx).
Conflict configuration for provider-owned conflicts is documented under [Conflicts](./conflicts.mdx).

## behavior

`behavior` contains shared runtime timings for all providers.

### attemptTtl

<Badge type="warning">Advanced</Badge>

- Takes: a positive duration
- Current default: `"10m"`
- Affects: how long provider-attempt markers stay in the replicated attempt store

Identica uses this when it marks that a provider attempt already happened for a provider, scope, username, and IP combination.
Longer values make repeated attempts stay blocked longer.
Shorter values let retries happen sooner.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
behavior:
  attemptTtl: "10m"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "behavior": {
    "attemptTtl": "10m"
  }
}
```
  </Tab>
</Tabs>

## providers

- Takes: a list of provider entries
- Affects: provider enablement, ordering, entrypoint routing, provider-specific session behavior, feature-owned provider overrides

Provider ids should match installed provider descriptors, such as `premium` or `credential`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
providers:
  - id: "premium"
    displayName: "PR"
    enabled: true
    priority: 100
    entrypoints:
      - "premium.example.com"
    session:
      concurrencyPolicy: "REJECT_NEW"
```
  </Tab>
  <Tab value="JSON">
```json
{
  "providers": [
    {
      "id": "premium",
      "displayName": "PR",
      "enabled": true,
      "priority": 100,
      "entrypoints": ["premium.example.com"],
      "session": {
        "concurrencyPolicy": "REJECT_NEW"
      }
    }
  ]
}
```
  </Tab>
</Tabs>

### id

- Takes: a provider id string
- Affects: which installed provider descriptor this entry configures

This should match the provider's descriptor id exactly enough for case-insensitive lookup.

### displayName

- Takes: a string
- Current default: `""`
- Affects: the user-facing label used for this provider when one is needed

If this is blank, Identica falls back to the provider descriptor name and then the raw id.

### enabled

- Takes: `true` or `false`
- Affects: whether the provider is available for resolution and flow building

### priority

- Takes: an integer
- Affects: ordering when multiple providers are eligible

Higher values win before lower values.

### entrypoints

- Takes: a list of hostnames, optionally with `:port`
- Affects: hostname-based provider selection before normal fallback ordering

Entries must use the format `host` or `host:port`.
Leave the list empty if hostname-based provider selection is not part of your setup.

### session

Use `session` when one provider should behave differently from the global live-session defaults.

#### session.concurrencyPolicy

<Badge type="warning">Advanced</Badge>

- Takes: `"ALLOW_MULTIPLE"`, `"REPLACE_EXISTING"`, or `"REJECT_NEW"`
- Current default: absent
- Affects: how live-session replacement behaves for this specific provider

If this is absent, Identica uses `settings.sessions.concurrencyPolicy`.

### features

Use `features` for per-provider overrides of built-in behavior. Providers declare integration support through `supportedFeatures()`. Omitted settings inherit global defaults; explicit provider values override them.

- Takes: an object containing feature-owned configuration subtrees
- Current default: absent unless supplied by a feature
- Affects: provider-scoped overrides for selected features

The supported subtrees include:

- `features.recognition`: [Recognition](../features/recognition/index.mdx#provider-overrides)
- `features.restriction.join`: [Join restriction](../features/restriction/join/index.mdx#provider-overrides)
- `features.verification`: [Verification](../features/verification/settings/index.mdx#provider-overrides)

The `restriction-join` feature uses the nested `restriction.join` configuration path.
Provider ability IDs such as `authoritative-username` are code declarations, not configuration subtrees.
