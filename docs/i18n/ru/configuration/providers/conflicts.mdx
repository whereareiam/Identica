Конфигурация конфликтов определяет, как Identica разрешает конфликты провайдеров, например совпадения ников.

Этот документ находится в `providers/conflicts` и содержит необязательные общие переопределения для добавленных типов конфликтов. Ядро не поставляет правил по умолчанию для ников. Своими значениями по умолчанию в `identity/username/conflicts` владеет обработка [ников](../identity/username/index.mdx) — обязательное поведение идентичности. Запись `rules.username` в `providers/conflicts` имеет приоритет над этими правилами.

Конфликты настраиваются для каждого ключа конфликта.
Каждый ключ задаёт:

- правило `default`
- необязательные упорядоченные правила `cases`
- упорядоченный список обработчиков конфликтов внутри каждого правила

## rules

- Принимает: словарь, ключами которого служат ключи конфликтов
- Влияет на: то, как Identica разрешает зарегистрированные конфликты, прежде чем разрешить или запретить продолжение

Используйте этот раздел, если хотите переопределить цепочку обработчиков для типа конфликта или задать специфичное для типа поведение для подходящего селектора правила. Пример ниже — явное переопределение для ников, а не конфигурация, которую генерирует ядро. Чтобы использовать собственные правила подсистемы идентичности для ников, не добавляйте здесь `rules.username`.

<Tabs items={["YAML", "JSON"]}>
  <Tab value="YAML">
```yaml
rules:
  username:
    default:
      resolvers:
        - id: "format_display"
          parameters:
            format:
              pattern: "{username}*"
            target: "joiner"
    cases:
      - when:
          providers:
            - "premium"
            - "credential"
        resolvers:
          - id: "format_display"
            parameters:
              format:
                pattern: "{username}_{incomingProvider:8}"
              target: "joiner"
```
  </Tab>

## Выбор правила [#rule-selection]

Разрешая конфликт для ключа, например `username`, Identica проверяет правила в таком порядке:

1. подходящие правила из `cases`
2. правило `default`

Внутри правила обработчики выполняются в порядке списка.
Если обработчик возвращает `PASS`, Identica переходит к следующему обработчику.
Если все обработчики вернули `PASS`, Identica переходит к следующему подходящему правилу.
Если ни одно правило не дало результата, Identica записывает предупреждение в лог и разрешает конфликт.

Сопоставлением правил занимается добавленный тип конфликта для этого ключа.
Ядро хранит объект `when` как есть, но не интерпретирует его.

## rules.[key].default

- Принимает: объект правила конфликта
- Влияет на: резервную цепочку обработчиков для этого ключа конфликта

Правило `default` выполняется, когда ни одно подходящее правило из `cases` не дало результата, отличного от `PASS`.

## rules.[key].cases

- Принимает: список объектов правил конфликта
- По умолчанию: `[]`
- Влияет на: разрешение конфликтов средствами типа до выполнения правила по умолчанию

Каждое правило из `cases` проверяется в порядке списка.
Добавленный тип конфликта решает, подходит ли объект `when` правила к текущему контексту конфликта.

## rules.[key].cases[].when

- Принимает: объект
- По умолчанию: `{}`
- Влияет на: то, к каким контекстам применяется правило, согласно добавленному типу конфликта

Структуру и смысл `when` определяет добавленный тип конфликта для этого ключа.

## rules.[key].default.force
## rules.[key].cases[].force

<Badge type="warning">Для опытных</Badge>

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: то, запускает ли Identica обработчик, даже если тот не объявляет поддержку этого ключа конфликта

Не включайте эту настройку, если не собираетесь намеренно обходить обычные проверки совместимости обработчиков.

## rules.[key].default.resolvers
## rules.[key].cases[].resolvers

- Принимает: список записей обработчиков
- Влияет на: упорядоченную цепочку обработчиков для выбранного правила

Каждая запись выбирает тип обработчика и передаёт его параметры конфигурации.

## rules.[key].default.resolvers[].id
## rules.[key].cases[].resolvers[].id

- Принимает: строку
- Влияет на: то, какой зарегистрированный обработчик конфликтов вызывается

Id обработчика должен совпадать с обработчиком, зарегистрированным добавленным типом конфликта или другим установленным модулем.

## rules.[key].default.resolvers[].parameters
## rules.[key].cases[].resolvers[].parameters

- Принимает: объект
- По умолчанию: `{}`
- Влияет на: поведение конкретного обработчика

Структура параметров зависит от выбранного типа обработчика.
Id обработчиков, схемы параметров и специфичные для типа селекторы `when` должен описывать модуль, который их добавляет.
