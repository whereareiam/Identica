Функция `restriction` — это встроенный каркас для типов ограничений, сигналов и действующих ограничений. Её глобальное значение `enabled` по умолчанию можно переопределить для каждого провайдера в `features.restriction.enabled`.

Общие настройки ограничений находятся в `features/restriction/settings`.
Переопределения ограничений для конкретного провайдера задаются в `providers[].features.restriction`.

## Настройки [#settings]

### toggleTtl

- Принимает: положительную длительность
- По умолчанию: `"365d"`
- Влияет на: сколько ограничение, включённое администратором, действует, прежде чем снимется само

Ограничение действует, пока администратор его не снимет или пока не пройдёт эта длительность — смотря что наступит раньше.

Действующие ограничения не хранятся в базе данных. С [репликацией](../../replication/index.mdx) они хранятся в Redis: каждый прокси сети видит ограничение сразу после его включения или снятия, а перезапущенный прокси видит его, пока оно есть в Redis. Без репликации они хранятся в памяти прокси, поэтому перезапуск прокси снимает все ограничения — после перезапуска включите их снова.

### replication.toggleNamespace

<Badge type="warning">Для опытных</Badge>

- Принимает: непустую строку
- По умолчанию: `"identica:restriction:toggle"`
- Влияет на: имя, под которым действующие ограничения передаются через репликацию

Прокси, которые должны делить ограничения, используют одно и то же значение.

## Типы ограничений [#restriction-types]

[Ограничение входа](./join/index.mdx) предоставляет отдельная функция `restriction-join`. Для неё также нужно выбрать `restriction`. Если выбрать только каркас, команды и проверки ограничения входа не устанавливаются.
