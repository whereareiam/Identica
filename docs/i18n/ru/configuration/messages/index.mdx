На этой странице описаны только общие разделы форматирования, которые влияют сразу на множество сообщений.
Разбирать каждое отдельное поле из полной конфигурации сообщений она не пытается.

Сообщения, относящиеся к функциям, хранятся в каталоге каждой функции. Сообщения об ошибках синхронизации ника и сообщения конфликтов ников настраиваются в [identity/username/messages](../identity/username/index.mdx#messages).

## Форматирование [#formatting]

В сообщениях Identica можно использовать форматирование MiniMessage.
Если вам нужны цвета, оформление текста, действия по клику и наведению или другие возможности форматирования, обратитесь к справочнику по формату MiniMessage:

- [Справочник по формату MiniMessage](https://docs.papermc.io/adventure/minimessage/format/)

Кроме того, в некоторых сообщениях Identica предоставляет собственные плейсхолдеры.
Они всегда записываются в фигурных скобках, например `{prefix}`, `{username}` или `{provider}`.

Какие именно плейсхолдеры доступны, зависит от конкретного поля сообщения и от того, какой код его выводит.

## Пустое сообщение [#emptying-a-message]

Сообщение, заданное пустой строкой, или многострочное сообщение, заданное пустым списком, не показывается. Это убирает только текст и больше ничего не меняет: игрок, которому отказано во входе, которого заблокировали или отключили, всё так же получит отказ, блокировку или отключение — просто без объяснения причины.

Исключение — коды восстановления: они показываются один раз, и прочитать их повторно нельзя. Поэтому, если тело их сообщения пустое или не содержит `{entries}`, коды отправляются отдельно.

## engine

Раздел `engine` содержит сообщения самого процесса входа. Два из них относятся к `settings.sessions.concurrencyPolicy` — настройке, которая определяет, что происходит, когда аккаунт, уже находящийся в сети, входит с другого подключения:

#### concurrentLoginKick

- Принимает: список строк
- Влияет на: причину, которую видит прежнее подключение, когда `REPLACE_EXISTING` его отключает, а также подключение, которое ещё входило, когда другое подключение вошло в аккаунт

#### concurrentLoginRefused

- Принимает: список строк
- По умолчанию: уведомление, которое заканчивается строками `This account is already logged in.` и `Log out from the other location first.`
- Влияет на: причину, которую видит новый вход, когда `REJECT_NEW` отклоняет его, потому что аккаунт уже в сети

Если очистить любое из этих сообщений, изменится только текст. Прежнее подключение всё равно будет отключено, а новый вход всё равно будет отклонён — в этом случае с общим сообщением сценария о неудаче.

#### usernameHeld

- Принимает: список строк
- По умолчанию: уведомление со строками `This name is being logged in from another location.` и `Try again shortly.`
- Влияет на: причину, которую видит подключение, отклонённое потому, что другое подключение с другого адреса входит под тем же именем на другом прокси сети

Когда Identica отклоняет такое подключение, описано в разделе [Входы в процессе](../engine/index.mdx#logins-in-progress). Если очистить сообщение, изменится только текст: подключение всё равно будет отклонено.

## routing

Identica отключает игрока, если сервера, на который его направляет маршрутизация, нет на прокси. Причина берётся из сценария, в котором находится игрок, а если у сценария её нет — из общего сообщения.

#### routing.missingServer

- Принимает: список строк
- По умолчанию: уведомление со строками `No target server available for routing` и `Please contact a server administrator.`
- Влияет на: причину, которую видит игрок, когда сервера маршрутизации нет, а у его сценария нет собственного сообщения или маршрут не относится ни к одному сценарию

#### scenarios.authentication.routing.missingServer, scenarios.registration.routing.missingServer, scenarios.migration.routing.missingServer

- Принимает: список строк
- По умолчанию: `[]`
- Влияет на: причину, которую видит игрок в этом сценарии, когда сервера маршрутизации нет

Если сообщение сценария пустое, показывается `routing.missingServer`. Чтобы отключать без причины, очистите оба.

## prefix

- Принимает: строку
- По умолчанию: `"<green>Identica</green> <dark_gray>| "`
- Влияет на: глобальный префикс сообщений, который передаётся движку сериализации

Этот префикс доступен в сообщениях через `{prefix}` и также служит источником префикса для сериализатора.

Изменив его, вы можете поменять брендинг или общий стиль сообщений Identica, не правя каждую строку сообщений по отдельности.

## format

Раздел `format` управляет общими вспомогательными средствами форматирования, которые используются плейсхолдерами сообщений.

### temporal

Подраздел `temporal` определяет, как форматируются общие плейсхолдеры даты и даты со временем, когда сообщения выводят метки времени.

#### date

- Принимает: строку шаблона даты и времени
- По умолчанию: `"dd.MM.yyyy"`
- Влияет на: шаблон форматирования для плейсхолдеров, содержащих только дату

Если значение пустое, код использует встроенный форматтер, предусмотренный для конкретного сообщения.

#### dateTime

- Принимает: строку шаблона даты и времени
- По умолчанию: `"dd.MM.yyyy HH:mm:ss"`
- Влияет на: шаблон форматирования для плейсхолдеров даты со временем

Если значение пустое, код использует встроенный форматтер, предусмотренный для конкретного сообщения.

## commands.pagination

Раздел `commands.pagination` настраивает общий механизм постраничного вывода для команд, вывод которых занимает несколько страниц.

Эти настройки влияют на оформление навигации по страницам, а не на то, какие данные разбиваются на страницы.

#### showPaginationIfOnePage

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: показываются ли элементы навигации, когда страница всего одна

#### format

- Принимает: строку
- По умолчанию: `"\n {previous}<white>Pagination</white> <gray>[{current}/{max}]</gray>{next} \n"`
- Влияет на: общий формат строки навигации по страницам

Механизм постраничного вывода может подставлять, например, такие плейсхолдеры:

- `{previous}`
- `{next}`
- `{current}`
- `{max}`

#### showPreviousEvenIfFirst

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: показывается ли кнопка перехода на предыдущую страницу на первой странице

#### previousTagFormat

- Принимает: строку
- По умолчанию: `"<red><click:run_command:/identica help {previousPage}>«</red> "`
- Влияет на: вид кнопки перехода на предыдущую страницу

Здесь механизм постраничного вывода может подставлять `{previousPage}`.

#### showNextEvenIfLast

- Принимает: `true` или `false`
- По умолчанию: `false`
- Влияет на: показывается ли кнопка перехода на следующую страницу на последней странице

#### nextTagFormat

- Принимает: строку
- По умолчанию: `" <green><click:run_command:/identica help {nextPage}>»</green>"`
- Влияет на: вид кнопки перехода на следующую страницу

Здесь механизм постраничного вывода может подставлять `{nextPage}`.
